title: Reverse proxy

Freenary serves plain HTTP; your proxy adds HTTPS and the hostname. Use one hostname unless you need the API on its own. Dokploy and Coolify set this up for you.

## One hostname

Send your hostname to the web app on port `3001`. The web app forwards four path prefixes to the API server over the Docker network: `/api/auth`, `/rpc`, `/ai/chat` and `/api-reference`. It forwards only when `SERVER_URL` is set, which both Compose files do.

The forwarded request keeps its method, body and headers, minus `Host` and the hop-by-hop headers. The web app replaces `X-Forwarded-For` with the caller address it resolves: see [Trusted proxies](#trusted-proxies). Redirects come back unchanged. The API server must start answering within the [9-second limit](/docs/reference/api#base-url).

The API server publishes no port, so every API call goes through the web app. With the root `docker-compose.yml`, set both URLs to your address, bind the web port to the loopback interface so only the proxy reaches it, and [trust your proxy](#trusted-proxies):

```dotenv
BETTER_AUTH_URL=https://freenary.example.com
CORS_ORIGIN=https://freenary.example.com
WEB_PORT=127.0.0.1:3001
TRUSTED_PROXIES=172.18.0.0/16
```

Caddy gets its certificate itself:

```text
freenary.example.com {
	reverse_proxy 127.0.0.1:3001
}
```

nginx, with a Certbot certificate:

```text
server {
    listen 443 ssl;
    server_name freenary.example.com;

    ssl_certificate     /etc/letsencrypt/live/freenary.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/freenary.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
```

A proxy container on a Docker network can run `deploy/docker-compose.yml` instead, which publishes no port. Set `FREENARY_URL`, attach the `web` service to the proxy's network, and route your hostname to `web` on port `3001`. Add no route to `server`.

## Two subdomains

Send both hostnames to the web app on port `3001`, for example `app.example.com` and `api.example.com`. The web app forwards the API paths of either one to the server:

```dotenv
BETTER_AUTH_URL=https://api.example.com
CORS_ORIGIN=https://app.example.com
AUTH_COOKIE_DOMAIN=.example.com
WEB_PORT=127.0.0.1:3001
TRUSTED_PROXIES=172.18.0.0/16
```

`CORS_ORIGIN` must match the web app's address exactly. `AUTH_COOKIE_DOMAIN` keeps the session cookie at `SameSite=Lax` on both hostnames. Without it the cookie falls back to `SameSite=None`, which browsers that block third-party cookies drop.

The `server` container refuses to start when:

- `AUTH_COOKIE_DOMAIN` ends with a dot, has a single label, or isn't a parent of both hostnames;
- the hostnames differ, `AUTH_COOKIE_DOMAIN` is unset, and `BETTER_AUTH_URL` uses `http://`.

A public suffix such as `.co.uk` isn't detected: name a domain you own.

## Trusted proxies

Rate limits count per caller address. The web app works it out from the connection it receives, and sends only that address to the API server:

- **The connection comes from an address in `TRUSTED_PROXIES`:** the web app reads `X-Forwarded-For` from the right and takes the first address that isn't listed.
- **Any other connection:** the web app takes the connection's own address and ignores the header, so a caller can't pick its address.

Leave `TRUSTED_PROXIES` unset only when visitors reach the web app with no proxy in front. Behind an unlisted proxy, every visitor counts as the proxy's address and shares one limit, so one visitor can use up everyone's sign-in attempts. The `server` container logs a warning at start while `TRUSTED_PROXIES` is unset.

List the addresses your proxy uses to reach the web container, as addresses or CIDR ranges, comma-separated. A proxy on the host reaches it from the Compose network. Print that network's range:

```bash
docker network inspect freenary_default --format '{{range .IPAM.Config}}{{.Subnet}}{{end}}'
```

On Dokploy or Coolify, inspect the panel's proxy network instead: `dokploy-network` or `coolify`. Put the range in `.env` or the panel's environment, then run `docker compose up -d` or redeploy:

```dotenv
TRUSTED_PROXIES=172.18.0.0/16
```

Write IPv4 in IPv4 form: `::ffff:10.0.0.1` stops the start. Behind a CDN, also list its published ranges, and make your proxy keep the CDN's `X-Forwarded-For` instead of replacing it.

## Check it

```bash
curl -L -o /dev/null -w '%{http_code} %{url_effective}\n' https://freenary.example.com/
curl https://freenary.example.com/api/auth/ok
```

The first prints `200 https://freenary.example.com/login`, the second `{"ok":true}`. With two subdomains, `curl https://api.example.com/api/auth/ok` prints `{"ok":true}`.

A `502` with the body `Bad Gateway` means the web app didn't reach the API server: read `docker compose logs server`.
