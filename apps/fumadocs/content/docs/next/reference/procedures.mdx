All 58 procedures, grouped by router. [API](/docs/reference/api) covers the base URL, the cookie, the request shapes and the rate limits.

- **Path.** `budget.getTransactions` is `POST /rpc/budget/getTransactions` or `POST /api-reference/budget/getTransactions`.
- **Input.** `/api-reference/spec.json` on your instance holds every input schema: types, required fields, enums, bounds and defaults. This page adds only the rules a schema can't express.
- **Access.** **Public** needs no session. **Protected** needs the session cookie, or returns `UNAUTHORIZED` (401). **Operator** also returns `FORBIDDEN` (403) to any account that isn't the operator.
- **Errors.** A procedure with no **Errors** line has no failure of its own. The 401, the 403, a failed schema and an unhandled `INTERNAL_SERVER_ERROR` can still happen.
- **Dates** are ISO 8601 strings. **Money** is an integer in minor units: 12.34 EUR is `1234`. Sums add stored amounts with no currency conversion, so a total over two currencies mixes them.

## Date ranges and aggregation

`from` and `to` are both included. Nothing checks that `from` comes before `to`.

Five procedures take `aggregation`: `getBudgetVsActual`, `getFixedVsVariable`, `getPeriodOverview`, `getSankeyData` and `getSpendingBreakdown`. `total` sums the range. `average` and `median` work on monthly sums, over the months that hold at least one transaction the procedure reads, so an empty month doesn't count as zero.

## Root procedures

### healthCheck

**Output**: the string `"OK"`.

## `assistant`

A conversation is one chat in **Ask**. Every procedure that takes a `conversationId` acts only on the caller's own chats.

### assistant.createConversation

**Output**: `{ conversationId }`. Pass it as `id` to the [assistant stream](/docs/reference/api#assistant-stream) or as `conversationId` to `saveTurn`. The chat has no title and no message yet, so `listConversations` leaves it out until a turn is stored.

### assistant.deleteConversation

**Input**: `conversationId`. An id that isn't the caller's deletes nothing.

**Output**: `{ ok: true }`. A dashboard built in the chat stays.

### assistant.getConversation

**Input**: `{ conversationId }`.

**Output**: `{ conversationId, messages, title }`.

- `messages` is the stored transcript, oldest first, as `{ id, parts, role }`. `role` is `user` or `assistant`, `parts` is the AI SDK `UIMessage.parts` array, and `id` is what you pass as `messageId` to redo that turn.
- `title` is the first question, cut to 80 characters, or `null` before the first stored turn.

**Errors**: `NOT_FOUND` (404) `Conversation not found`, when the chat isn't the caller's.

### assistant.getStatus

**Output**: `{ serverModel }`, the model id of the instance, or `null` when it has none.

### assistant.listConversations

**Output**: `{ conversations }` of `{ id, title, updatedAt }`, most recently updated first, at most 50. Only chats that hold at least one message are listed.

### assistant.saveTurn

**Input**: `conversationId` must name one of the caller's chats. `answer.id` becomes the id of the answer row. `regeneratedMessageId` names the stored answer this turn replaces.

**Output**: `{ ok: true }`.

**Errors**, in the order they're checked:

- `TOO_MANY_REQUESTS` (429): over the [rate limit](/docs/reference/api#rate-limits).
- `BAD_REQUEST` (400) `Turn too large`: the question exceeds 8000 characters, or the answer parts exceed 200000 characters as JSON.
- `NOT_FOUND` (404) `Conversation not found`.
- `BAD_REQUEST` (400) `Empty answer`: no text part and no resolved tool part survived the filter.

## `bankConnection`

### bankConnection.disconnect

**Input**: `connectionId` must belong to the caller.

**Output**: `{ accountsRemoved, institutionName, revocationRequested }`. `revocationRequested` is `false` when the provider refused the revoke call or has no credentials; the connection is deleted either way.

**Errors**: `NOT_FOUND` (404) `Bank connection not found`.

### bankConnection.exchangeCode

**Input**: `params` is the raw callback query and must hold a `state` key. It takes at most 20 keys, each key at most 100 characters and each value at most 4096. `providerId` is `powens`, `enable-banking` or, outside production, `mock`.

**Output**: `{ accounts, connectionId, institutionName, returnTo, sessionId, syncStartedAt }`. `accounts` lists `{ iban?, name?, uid }` as the provider returned them. `returnTo` is `onboarding` or `settings`, as signed into the state. `sessionId` is the provider's session id.

The procedure starts the new connection's first sync before it returns, as `budget.syncAccounts` with this `connectionId` would. `syncStartedAt` is the date to pass to `budget.getSyncOutcome`, or `null` when none started, usually because another sync was already running.

**Errors**

- `NOT_FOUND` (404) `Unknown banking provider`.
- `BAD_REQUEST` (400) `Missing bank connection state`, `Invalid bank connection state`, `Invalid banking provider in connection state`, `Bank connection state does not belong to this session`, `Bank connection state has expired or was already used`, `Bank institution is no longer available`, or `No provider session for this user`.
- `SERVICE_UNAVAILABLE` (503) `Could not load banks for this country`.

### bankConnection.getProviderAvailability

**Output**: `{ available }`, `false` when the provider credentials are absent.

### bankConnection.listConnections

**Output**: `{ connections }`, oldest first. Each connection is:

| Field | Note |
| --- | --- |
| `accounts` | `{ iban, id, name }`, oldest first |
| `id` | Pass it as `connectionId` to `disconnect` or `budget.syncAccounts` |
| `institutionCountry` | The bank's country code, or `null` |
| `institutionId`, `institutionName` | The bank, as the provider names it |
| `lastSyncedAt` | `null` before the first sync |
| `status` | `ACTIVE`, `EXPIRED` or `ERROR`. Only `ACTIVE` connections sync |

### bankConnection.listInstitutions

**Input**: leave `countries` out, or send `[]`, to use the caller's tax countries.

**Output**: `{ banks, unavailableCountries }`. A bank is `{ bic, country, id, logo, name }`; `bic` and `logo` can be `null`. Pass `id` as `institutionId` to `startConnection`.

The provider answers one country at a time and the result is the union. A bank is the pair of `id` and `country`, and a duplicate pair is dropped. `unavailableCountries` lists the countries whose provider call failed. A country with no bank isn't listed there.

**Errors**: `BAD_REQUEST` (400) `No country to list banks for`, when the input and the account both hold no country.

### bankConnection.startConnection

**Input**: `institutionId` is an `id` from `listInstitutions`, and `bankCountry` must match its country. `state` is your own value, returned in the callback state.

**Output**: `{ url }`. Send the user's browser there. The provider redirects back to `CORS_ORIGIN` plus `/callback/powens` or `/callback/enable-banking`, a page of the web app.

**Errors**: `BAD_REQUEST` (400) `Unknown bank institution`; `SERVICE_UNAVAILABLE` (503) `Could not load banks for this country`.

## `budget`

### budget.deleteSavedFilter

**Input**: `id` must belong to the caller.

**Output**: `{ id }`.

**Errors**: `NOT_FOUND` (404) `Saved filter not found`.

### budget.getAccounts

**Output**: `{ accounts, currency, firstTransactionDate, hasAccounts, lastTransactionDate }`. `accounts` holds `{ iban, id, institutionName, name }` in no set order. `currency` is the code most of the caller's accounts use, or `EUR` when none has one. `getBudgetVsActual`, `getCashFlow`, `getFixedVsVariable`, `getPeriodOverview`, `getSankeyData`, `getSpendingBreakdown`, `getSpendingByWeek`, `getTransactions`, `settings.getBudgetProfile` and the two `portfolio` procedures return the same one. The two dates bound the caller's transactions, and are `null` when there are none.

### budget.getBudgetVsActual

**Output**: `{ categories, currency, hasPlan }`. `categories` holds `{ actual, category, planned }` for each category whose plan or spend isn't zero, largest planned first, then largest actual. `hasPlan` is `false` with no outgoing budget line.

With `average` or `median`, `planned` is the monthly plan. With `total`, it's the monthly plan times the months from `from` to `to` or today, whichever comes first: average-length months, rounded, at least 1.

### budget.getCashFlow

**Output**: `{ currency, periods }`, with `periods` of `{ incoming, label, outgoing }`, oldest first. `label` is a day (`YYYY-MM-DD`), the Monday of a week, or a month (`YYYY-MM`).

**Input**: `grain` is `day`, `week` or `month`. Leave it out to let the range decide: days up to 31 days, weeks up to 93 days, and months beyond.

### budget.getFixedVsVariable

**Output**: `{ currency, fixed, variable }`. The two sum to the money out, aggregated as asked.

### budget.getMerchants

**Input**: `search` is at most 200 characters and matches the counterparty name, or the descriptor when there is none, as a plain substring, without case. `%` and `_` in it are literal.

**Output**: `{ merchants }` of `{ count, name, totalMinor }`, highest count first, then by name. `totalMinor` sums absolute amounts.

### budget.getPeriodOverview

**Output**: `{ budgetVsActual, fixedVsVariable, sankey, spendingBreakdown }`, each the output of `getBudgetVsActual`, `getFixedVsVariable`, `getSankeyData` and `getSpendingBreakdown` for the same input. It reads the range once instead of four times.

### budget.getRecurring

The rules behind `confidence` and `kind` are in [`docs/engineering/categorisation.md`](https://github.com/suiramdev/freenary/blob/dev/docs/engineering/categorisation.md#recurrence-detection).

**Output**

| Field | Note |
| --- | --- |
| `asOf` | When the detection ran. Every projection counts from here |
| `availableBalanceMinor` | The sum of the `CHECKING` account balances in `currency`, or `null` when none reports one |
| `currency` | The most common currency of the `CHECKING` accounts, else `EUR` |
| `items` | One detected pattern per entry, without the ones whose last charge is older than their band's longest gap |
| `monthly` | The trailing 12 calendar months, oldest first, zero-filled: `{ month, fixedMinor, behavioralMinor, discretionaryMinor }`, `month` as `YYYY-MM` |
| `monthlyIncomeMinor` | Money in over the 365 days before `asOf`, divided by the months since the first incoming transaction, or `null` |
| `plannedOutgoingMinor` | The monthly sum of outgoing budget lines, or `null` with no plan |

| Field of one item | Note |
| --- | --- |
| `amountSpread` | Relative spread of the amounts. `0` when all are equal |
| `category` | A spending category slug |
| `confidence` | `confirmed`, `likely` or `pattern` |
| `currency` | ISO 4217 code of the latest occurrence |
| `frequency` | `weekly`, `monthly`, `quarterly`, `annual` or `irregular` |
| `intervalDays` | Median gap between occurrences, in days |
| `kind` | `fixed` or `behavioral` |
| `lastSeen`, `nextExpected` | ISO 8601 date-times |
| `merchantKey`, `merchantName` | The merchant lookup key, and the latest counterparty name or `null` |
| `occurrences` | Transactions in the 790 days before `asOf` |
| `typicalAmountMinor` | Positive |

### budget.getRecurringExpenses

**Output**: `{ expenses }`, largest typical amount first. Each entry has the fields of a `getRecurring` item except `amountSpread`, `confidence` and `kind`. `occurrences` counts inside a 790-day window.

### budget.getSankeyData

**Output**: `{ currency, groups, incomeNodes, moneyLeft, totalExpenses, totalIncome }`.

- `groups` holds `{ categories, group, value }`, with `{ category, value }` rows in `categories`.
- `incomeNodes` holds `{ name, value }`: the 10 largest sources by counterparty name, then one node with `name: null` for the rest. Money in with no counterparty name joins that `null` node before the top 10 are picked, so it can rank among them.
- `moneyLeft` is `totalIncome` minus `totalExpenses`, never below 0.

Internal transfers count as income and as spending.

### budget.getSpendingBreakdown

**Output**: `{ categories, currency }`, with `categories` of `{ amount, category }`, largest first.

### budget.getSpendingByWeek

**Input**: `to` is the last day counted. `weeks` is a whole number from 1 to 26.

**Output**: `{ currency, weeks }`, with one entry per week, oldest first, the last one holding `to`. A week is `{ categories, start, totalMinor }`: `start` is its Monday as `YYYY-MM-DD`, `categories` holds `{ amountMinor, category }`, largest first, and `totalMinor` sums them. Only money out in a category of the `spending` group counts, as a positive amount.

### budget.getSyncOutcome

**Input**: `startedAt`, as `budget.syncAccounts` returned it.

**Output**: `null` while that sync runs, then `{ categorised, failures, success }`. `failures` lists what went wrong: `{ kind: "connection-sync", connectionId, institutionName }` for each connection that failed, and `{ kind: "categorisation" }` when sorting the transactions failed. `success` is `false` when at least one connection failed.

**Errors**: `NOT_FOUND` (404) `The sync run ended without an outcome`, when the run crashed, went silent for 5 minutes, or a later run replaced it.

### budget.getSyncStatus

**Output**: `null` when nothing runs, or `{ accountsDone, accountsTotal, categorised, categorisedTotal, phase, startedAt, transactionsImported }`. `phase` is `importing` or `categorising`. `categorisedTotal` is `0` until categorising starts. `transactionsImported` counts new and updated rows alike.

Poll it during a sync: it reads one row and calls no provider. Counters update at most once a second. A run silent for 5 minutes reads as `null`.

### budget.getTransactions

The one paged procedure: pass `nextCursor` back as `cursor`.

**Input**

- `limit` is a whole number from 1 to 100.
- `accountId`, when set, keeps the transactions of that one account. An account of another user matches nothing.
- `filters` holds up to 20 filters, and a transaction must match all of them, and `direction` and `search` too. A filter is `{ field, operator, values }` for `field` `company`, `category` or `account`, and `{ field: "amount", operator, value }` for an amount.
  - `company`, `category` and `account` take `operator` `is`, `isNot` or `isAnyOf`. `is` and `isNot` take exactly one value, `isAnyOf` up to 50.
  - A `company` value is a name as `getMerchants` returns it, matched without case against the counterparty name, or the normalised descriptor when there is none. `isNot` keeps a transaction with no company name.
  - A `category` value is a category slug or a group slug, and a group stands for every category in it. A transaction no step has categorised counts as `uncategorised`.
  - An `account` value is an account id from `getAccounts`. An id of another user's account matches nothing.
  - `amount` takes `operator` `gt`, `lt` or `eq`, and compares `value`, in minor units, with the absolute amount. `gt` and `lt` are strict, and `eq` matches exactly.
- `search` is at most 200 characters and matches the description or the counterparty name as a plain substring, without case.
- `sort: "amount"` puts the largest first: descending for `direction: "incoming"`, most negative first otherwise.

**Output**: `{ currency, nextCursor, totals, transactions }`. `currency` is the currency of `totals`. `nextCursor` is `null` on the last page. `totals` is `{ incoming, outgoing }` over the whole filter, not the page, both positive, on the first page only: a page read with a `cursor` returns `null`.

| Field of one transaction | Note |
| --- | --- |
| `amount` | Negative for money out |
| `category` | The effective category: the user's override wins |
| `derivedCategory` | What the pipeline resolved, before any override |
| `counterpartyName` | As the bank sends it, or `null` |
| `normalisedDescriptor` | The bank's label cleaned by the categorisation pipeline, or `null` |
| `currency`, `date`, `description`, `id` | As stored |

### budget.listSavedFilters

**Output**: `{ savedFilters }` of `{ filters, id, name, search }`, sorted by name without case. `filters` has the shape `getTransactions` reads. A stored filter that no longer passes its schema, such as one naming a removed category, is left out, and a saved search left with no filter and no text is left out too.

### budget.recategorise

Drops the pipeline's verdicts and runs it again over every transaction. It claims the caller's sync run first, so it refuses while a sync runs, and `getSyncStatus` shows it in the `categorising` phase.

**Output**: `{ categorised, started }`. `started: false` and `categorised: 0` mean another run already holds the user.

### budget.saveFilter

**Input**: `name` is trimmed, at most 60 characters. `filters` follows `getTransactions`. `search` is the free text, at most 200 characters. At least one filter or some non-blank text is required.

Saving under a name the caller already uses, compared without case, replaces that saved search and takes the new spelling.

**Output**: `{ id, name, replaced }`. `replaced` is `true` when a saved search with that name already existed.

**Errors**: `SAVED_FILTER_LIMIT` (400) `Keep at most 50 saved filters`, when the name is new and the caller already has 50.

### budget.syncAccounts

**Input**: send `{}` to sync every `ACTIVE` connection of the caller. `connectionId` narrows it to one; an id that isn't the caller's or isn't `ACTIVE` syncs nothing and still answers `success: true`. `force: true` reads the whole 90-day provider window again.

**Output**: `{ startedAt }`. It answers as soon as the sync starts, and the sync goes on without the request. Poll `budget.getSyncOutcome` with `startedAt` to learn how it ended. `startedAt: null` means another run holds the user and nothing started: one sync runs per user, so follow `budget.getSyncStatus` instead.

### budget.updateTransactionCategory

**Input**: `transactionId` must belong to the caller. `category: null` clears the override.

**Output**: `{ additionalUpdated, category, derivedCategory }`: how many other transactions of the merchant moved, the effective category, and what the pipeline resolves without the override.

The category is remembered for the merchant and copied to its other transactions that have no override of their own; `null` forgets it and clears theirs. A transaction with no merchant key changes alone and `additionalUpdated` is `0`.

**Errors**: `NOT_FOUND` (404) `Transaction not found`.

## `dashboards`

A dashboard is a `title`, at most 60 characters, and an ordered `widgets` array of 1 to 12 entries. Each widget is an object whose `type` is `stat`, `spending_by_week`, `income_vs_spending`, `budgets`, `top_categories`, `upcoming_bills`, `net_worth`, `accounts` or `transactions`, with an optional `title` of at most 60 characters. The spec lists the fields and bounds of each. A widget stores no figure: the app reads the data when it shows the dashboard.

### dashboards.create

**Input**: `conversationId`, when set, links the dashboard to that chat. An id that isn't the caller's leaves it unlinked.

**Output**: `{ dashboardId, title }`.

**Errors**: `BAD_REQUEST` (400) `A user keeps at most 30 dashboards`.

### dashboards.delete

**Input**: `dashboardId`. An id that isn't the caller's deletes nothing.

**Output**: `{ ok: true }`. The chat the dashboard came from stays.

### dashboards.get

**Output**: `{ conversation, id, title, updatedAt, widgets }`. `conversation` is `{ id, title }` of the chat the dashboard was built in, or `null`. A stored widget that no longer passes its schema is left out of `widgets`.

**Errors**: `NOT_FOUND` (404) `Dashboard not found`.

### dashboards.list

**Output**: `{ dashboards }` of `{ id, title, updatedAt, widgetTypes }`, most recently updated first. `widgetTypes` lists the `type` of each widget, in order.

### dashboards.update

**Input**: `dashboardId`, plus `title`, `widgets` or both. `widgets` replaces the whole list.

**Output**: `{ dashboardId, title }`.

**Errors**: `NOT_FOUND` (404) `Dashboard not found`.

## `instance`

The procedures behind the setup screen and Settings, under **Connections** › `Services`. Integrations are `banking` (variants `disabled`, `powens`, `enable-banking`), `email` (variants `disabled`, `resend`, `smtp`), `assistant` (variants `disabled`, `openai-compatible`) and `categorisation` (variants `disabled`, `jev`, `subq-snap`, `llm`, and `von`, `laya`, `system-one` and `zero-shot`, listed only while in use).

### instance.status

**Output**: `{ claimed, completed, isOperator }`. `claimed` is `true` once an operator exists, `completed` once the operator pressed `Finish setup`.

### instance.update

**Output**: `{ current, latest }`. `current` is the version the server runs, or `null` for a build without one. `latest` is the newest stable release when it's newer than `current`, and `null` otherwise, while the update check is off, and for any account that isn't the operator.

### instance.describe

**Output**: `{ fault, integrations, restartRequired }`. `fault` says why the stored values were rejected at startup, or is `null`. `restartRequired` is `true` when a saved value isn't in use yet.

| Field of one integration | Note |
| --- | --- |
| `id`, `selectedVariantId` | The integration and the variant in use |
| `shownInSetup`, `requiredForSetup` | Whether the setup screen shows the integration, and whether `instance.complete` needs it `configured` |
| `state` | `disabled`, `incomplete` or `configured` |
| `configuredBy` | `environment`, `instance` or `null` |
| `discriminantKey`, `discriminantSource` | The variable that picks the variant, such as `BANKING_PROVIDER`, and whether it comes from `environment`, `instance` or is `unset` |
| `variants` | `{ id, fields, legacy, recommended }`. `legacy` is `true` for a variant listed only while in use, `recommended` for one the screen marks `Recommended`. A field is `{ key, kind, present, required, source, suggestion, value }`; `value` is `null` for a secret and masked when the environment owns a text or URL value, and `suggestion` is the value the form starts from, or `null` |

### instance.check

**Input**: `integrationId` and `variantId` name one integration and variant. `values` maps a variable name to its value; the server fills in what the environment owns.

**Output**, by `outcome`:

| `outcome` | Other fields | Meaning |
| --- | --- | --- |
| `verified` | — | The provider accepted the credentials. A `disabled` variant, with nothing to check, also answers `verified` |
| `probe-failed` | `detail`, `reason`, `status` | The provider refused, timed out after 10 s, or couldn't be reached. `status` is the HTTP status of a refusal, else `null`. `detail` holds at most the first 300 characters of the answer or error |
| `missing-fields` | `keys` | Required fields are empty |
| `invalid` | `detail` | A value fails validation |
| `environment-owned` | `keys` | The environment picks another variant; `keys` names the variable |

**Errors**: `NOT_FOUND` (404) `Unknown integration` or `Unknown variant`.

### instance.save

Same input as `instance.check`. It stores only the values the environment doesn't set, and clears the stored values of the integration's other variants. Saving `disabled` answers `saved` and clears every stored value of that integration.

**Output**: `{ outcome: "saved", restartRequired: true }`, with `restartRequired` always `true`; `{ outcome: "nothing-to-save" }` when the environment owns the whole variant; or the `missing-fields`, `invalid` or `environment-owned` refusal of `instance.check`. Nothing restarts until `instance.complete`, which decides whether a restart is needed. To skip setup, save `disabled` for each integration, then call `instance.complete`.

**Errors**: `NOT_FOUND` (404) `Unknown integration` or `Unknown variant`.

### instance.complete

**Output**: `{ completed: true, restarting }`. `restarting` is `true` when a saved value isn't in use yet; the server then exits 250 ms later, and its restart policy starts it with the new values.

**Errors**: `PRECONDITION_FAILED` (412) `Configure a bank provider before finishing setup`, with `data.missing` listing each required integration that isn't `configured`. Setup stays not completed.

### instance.bankConnectionCount

**Output**: `{ count }`, the number of bank connections on the instance, across every member.

## `portfolio`

### portfolio.getBalanceHistory

**Input**: `today` is the last day counted. `months` is a whole number from 1 to 24.

**Output**: `{ currency, points }`. `points` holds `{ balanceMinor, date }`: the net worth at the end of each of the `months` months before the month of `today`, oldest first, then today's. `date` is `YYYY-MM-DD`. `points` is `null` when no account in `currency` reports a balance.

The history starts from today's balances in `currency` and takes back each later transaction of those accounts. An account with no transactions, such as most investment accounts, keeps its latest balance for every month.

### portfolio.getOverview

**Output**: `{ accounts, currency, currentAccounts, holdings, netWorth }`. `currency` is the code most of the caller's accounts use, or `EUR` when none has one; `netWorth` and `holdings` count only what is in that currency.

- `accounts` holds `{ balanceMinor, currency, id, institutionName, name, type }`, oldest first. `type` is `CHECKING`, `SAVINGS`, `CARD`, `LOAN`, `BROKERAGE`, `LIFE_INSURANCE`, `RETIREMENT`, `EMPLOYEE_SAVINGS`, `REAL_ESTATE`, `CROWDLENDING` or `UNKNOWN`. `balanceMinor` and `currency` are `null` when the provider sent none.
- `currentAccounts` is `{ balanceMinor, balancesAt, currency }`: the sum of the `CHECKING` balances in the currency most of them use, or `EUR` when none has one, and the latest balance date among the accounts it adds up. `balanceMinor` and `balancesAt` are `null` when no such account reports a balance.
- `netWorth` is `{ assetClasses, assetsMinor, balancesAt, excludedAccountCount, liabilitiesMinor, netWorthMinor }`. A balance below zero counts in `liabilitiesMinor`, as a positive amount; every other balance counts in `assetsMinor` and in its entry of `assetClasses`, `{ amountMinor, assetClass }`, where `assetClass` is `cash`, `savings`, `investments`, `property` or `other`. `excludedAccountCount` counts the accounts with no balance or in another currency. `balancesAt` is the latest balance date, and `netWorthMinor` is `null` when no account counts.
- `holdings` is `{ costBasisMinor, holdingCount, topHoldings, unrealisedGainMinor, valuationMinor }`. `unrealisedGainMinor` and `costBasisMinor` sum the holdings that report a gain, and are `null` when none does. `topHoldings` holds the three largest, `{ id, label, unrealisedGainMinor, valuationMinor }`.

## `settings`

A category key is a spending category slug, or `custom:<id>` for a custom category. The spec lists the slugs, with the group slugs, as the enum of a `category` filter of `budget.getTransactions`.

### settings.createCustomCategory

**Input**: `parentKey` is a category group slug, the `custom:<id>` of a top-level category the caller owns, or `null` for a top-level category.

**Output**: `{ key }`, the `custom:<id>` of the new category.

**Errors**

- `BAD_REQUEST` (400) `Unknown parent category` or `A subcategory cannot hold subcategories`.
- `NOT_FOUND` (404) `Parent category not found`.
- `CONFLICT` (409) `A category with that name already exists`, compared without case.

### settings.deleteCustomCategory

**Input**: `id` is the row id, not the `custom:` key, and must belong to the caller.

Deletes the category and its subcategories, and moves their budget lines to one fallback slug. Under a group, that's the group's catch-all: `other-income`, `savings` or `uncategorised`. A top-level category, or a subcategory under a custom parent, falls back to `uncategorised`, not to the parent.

**Output**: `{ deletedSubcategories, fallbackSlug, reassignedLines }`.

**Errors**: `NOT_FOUND` (404) `Category not found`.

### settings.getBudgetProfile

**Output**: `{ currency, lines }`, with `currency` as in `budget.getAccounts` and `lines` in saved order, each `{ amount, categoryKey, id, label }`. `amount` is minor units per month. `label` is `null` when the line has no name.

### settings.listCategories

**Output**: `{ categories }`, a flat array in display order: each of the 3 groups, its built-in categories, then the caller's custom categories under it; then each top-level custom category in stored order, followed by its subcategories.

| Field | Note |
| --- | --- |
| `key`, `parentKey` | The entry's key, and its group slug, `custom:<id>` parent, or `null` at top level |
| `label` | Custom categories only: the name the user gave it. A built-in entry carries no label: map its `key` to a display name |
| `icon` | An icon name |
| `color` | What the entry shows. Under a parent, the parent's colour. A built-in category shows `slot` instead |
| `slot` | Built-in categories only: the category's own palette slot, such as `teal` or `orange-alt` |
| `pickedColor` | Custom categories only: the stored colour. Send it back as `color` to `updateCustomCategory` to keep it |
| `isGroup` | `true` for a group header or a top-level custom category |
| `isAssignable` | `false` for a built-in group header |
| `isCustom` | `true` for the caller's own category |
| `usageCount` | Budget lines on a custom category. `0` for a built-in one |

### settings.moveCustomCategory

**Input**: `id` must belong to the caller. The category swaps with its neighbour under the same parent.

**Output**: `{ moved }`, `false` when the row is already first or last.

**Errors**: `NOT_FOUND` (404) `Category not found`.

### settings.saveBudgetProfile

**Input**: each `categoryKey` is a spending category slug or a `custom:<id>` the caller owns; a group slug fails. Array order becomes sort order. `label` has no default: send `""` for a line with no name.

**Output**: `{ lineCount }`.

**Errors**: `BAD_REQUEST` (400) `Unknown category: <categoryKey>`.

<Callout type="warn">

The write replaces every line: a line missing from the array is deleted.

</Callout>

### settings.updateCustomCategory

**Input**: `id` must belong to the caller. `parentKey` follows the rules of `createCustomCategory`.

**Output**: `{ success: true }`.

**Errors**

- `BAD_REQUEST` (400) `Unknown parent category`, `A subcategory cannot hold subcategories`, `A category with subcategories cannot be nested`, or `A category cannot be its own parent`.
- `NOT_FOUND` (404) `Category not found` or `Parent category not found`.
- `CONFLICT` (409) `A category with that name already exists`.
