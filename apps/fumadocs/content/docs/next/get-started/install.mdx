Pick the tab that matches your server. Each one ends with Freenary running at `https://freenary.example.com`, so replace that hostname with your own everywhere on this page. Check [Before you install](/docs/get-started/before-you-install) first.

<Tabs items={["Dokploy", "Coolify", "Docker Compose"]}>

<Tab value="Dokploy">

1. In a Dokploy project, create a **Compose** service of type **Docker Compose**.
2. In **General**, set the provider to **Git**:
   - Repository URL: `https://github.com/suiramdev/freenary.git`
   - Branch: `dev`
   - Compose Path: `./deploy/docker-compose.yml`
3. Generate two secrets on any machine with OpenSSL:

   ```bash
   echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)"
   echo "BETTER_AUTH_SECRET=$(openssl rand -hex 32)"
   ```

4. In **Environment**, add these lines, with your hostname and the two printed lines:

   ```dotenv
   FREENARY_URL=https://freenary.example.com
   FREENARY_VERSION=latest
   POSTGRES_PASSWORD=<printed value>
   BETTER_AUTH_SECRET=<printed value>
   ```

5. In **Domains**, add one domain: service `web`, host `freenary.example.com`, container port `3001`, HTTPS on.
6. Press **Deploy**.

**Prefer one paste?** In a clone of the repository, run:

```bash
bun run deploy:dokploy
```

It prints a template. Create a Compose service, open **Advanced** → **Base64 import**, and paste it. The template generates both secrets and a test hostname on `http://`. That hostname can't link a bank, so change the host under **Domains** to yours with HTTPS on, set `FREENARY_URL` to the same `https://` address, and deploy again.

</Tab>

<Tab value="Coolify">

1. In a Coolify project, select **New** → **Docker Compose Empty**.
2. Paste the contents of [`deploy/coolify.yml`](https://raw.githubusercontent.com/suiramdev/freenary/dev/deploy/coolify.yml). Coolify generates the database password and the auth secret.
3. Set the domain of the `web` service to your hostname followed by the container port:

   ```text
   https://freenary.example.com:3001
   ```

   The `:3001` tells Coolify which container port to route to. Visitors still use the plain HTTPS address.

4. Press **Deploy**.

</Tab>

<Tab value="Docker Compose">

Use this tab when you run your own reverse proxy on the server, such as Caddy or nginx. Freenary listens on the loopback interface only, and your proxy sends `https://freenary.example.com` to `127.0.0.1:3001`. [Reverse proxy](/docs/reference/reverse-proxy) has proxy examples.

1. Download the Compose file:

   ```bash
   mkdir freenary && cd freenary
   curl -O https://raw.githubusercontent.com/suiramdev/freenary/dev/docker-compose.yml
   ```

2. Create the `.env` file. Replace the hostname on both URL lines first:

   ```bash
   cat > .env <<EOF
   FREENARY_VERSION=latest
   POSTGRES_PASSWORD=$(openssl rand -hex 16)
   BETTER_AUTH_SECRET=$(openssl rand -hex 32)
   BETTER_AUTH_URL=https://freenary.example.com
   CORS_ORIGIN=https://freenary.example.com
   SERVER_PORT=127.0.0.1:3000
   WEB_PORT=127.0.0.1:3001
   EOF
   ```

   Both URLs are the same address: the web app forwards API calls to the server, so one hostname serves everything.

3. Start Freenary:

   ```bash
   docker compose up -d
   ```

4. Point your proxy at `127.0.0.1:3001`.

</Tab>

</Tabs>

`FREENARY_VERSION=latest` follows each new release. To stay on one version, see [Updates and backups](/docs/run/updates-and-backups).

## Check that it works

Freenary starts in order:

1. The database starts and reports healthy.
2. `migrate` prepares the database, then exits. It runs again on every start.
3. The server starts once the migrations succeed.
4. The web app starts once the server reports healthy.

Then open `https://freenary.example.com`. You should see the **Welcome to Freenary** sign-in screen. Something else, or a stopped container? See [Freenary won't start](/docs/run/troubleshooting#freenary-wont-start).

## Create your account now

<Callout type="warn" title="The first account to get a session becomes the operator">

The operator is the only account that can change the instance's settings. Until someone claims it, anyone who reaches your address can, so create your account right away. When email is configured, the role goes to the first account that enters its emailed code.

</Callout>

1. Press **No account yet? Create one**. Freenary adds a **Name** field.
2. Fill in your email address, name and password, then press **Create account**.

If someone else got there first, see [The wrong account became the operator](/docs/run/troubleshooting#the-wrong-account-became-the-operator).

## The setup screen

You land on the setup screen, where the operator picks the bank provider and the categorisation model. Until you finish it, every account that signs in is sent there. It has three steps: **Bank**, **Categories** and **Done**.

**Bank** is required: **Finish setup** refuses until a bank provider is set up, because onboarding asks every account to connect a bank. **Categories** can be skipped. Keep this tab open and continue to [Connect a bank](/docs/get-started/connect-a-bank).

Email and the assistant aren't on the setup screen. The operator can set them up at any time in Settings, under **Connections**: see [Email](/docs/run/email) and [AI models](/docs/run/models#assistant).

<Callout type="warn">

Keep `BETTER_AUTH_SECRET` once the instance runs. Freenary encrypts the values you enter on the setup screen with it, so a new secret makes them unreadable. See [What a rotation costs](/docs/reference/security#what-a-rotation-costs).

</Callout>
