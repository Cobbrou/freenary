Freenary runs on a server you control, and you reach it through your own domain over HTTPS. Check this list first, so the install takes one pass.

## What you need

- **A server.** A VPS or a home server with Docker Engine and Docker Compose v2, or a hosting panel such as [Dokploy](https://dokploy.com) or [Coolify](https://coolify.io) that runs Docker for you.
- **A domain that points at the server.** One hostname is enough, for example `freenary.example.com`. Freenary serves the whole instance from it.
- **HTTPS.** Freenary ships no proxy and no certificates. Dokploy and Coolify provide HTTPS. On a plain Docker host, your own reverse proxy does, or a tunnel.

You need HTTPS to link a bank: the bank provider only sends you back to an `https://` address, see [The redirect URI must be HTTPS](/docs/reference/bank-providers#the-redirect-uri-must-be-https).

<Callout title="Getting a domain and HTTPS">

- **Buy a domain.** Add a DNS record that points a hostname, such as `freenary.example.com`, at your server's public IP address.
- **Free dynamic DNS, for a home server.** A service such as [DuckDNS](https://www.duckdns.org) gives you a hostname that follows your home IP address. Your router must forward ports 80 and 443 to the server.
- **A tunnel, when you can't open ports.** [Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/get-started/) and [Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel) publish a hostname over HTTPS with no open port.

</Callout>

## Try it on your own computer

You can run Freenary on `localhost` to look around. Follow the **Docker Compose** tab of [Install Freenary](/docs/get-started/install), with these changes to `.env`:

- Leave out the `BETTER_AUTH_URL` and `CORS_ORIGIN` lines. Their defaults, `http://localhost:3000` and `http://localhost:3001`, match the default ports.
- Keep `SERVER_PORT=127.0.0.1:3000` and `WEB_PORT=127.0.0.1:3001`, so only your computer reaches the instance.
- If another program holds one of those ports, or PostgreSQL's `5432`, pick free ones. For the web or API port, also set `BETTER_AUTH_URL` and `CORS_ORIGIN` to `http://localhost:<web port>`. For PostgreSQL, set `POSTGRES_PORT`.

Then open `http://localhost:3001`. You can't link a bank there, because the address isn't HTTPS.
