A hosting panel runs Docker Compose stacks for you, and it puts TLS and a hostname in front of them. Freenary ships three files for that job, in the `deploy/` folder of the repository:

| File | For | What it asks for |
| --- | --- | --- |
| `deploy/docker-compose.yml` | Dokploy, Portainer, or any proxy on a Docker network | `FREENARY_URL`, `POSTGRES_PASSWORD`, `BETTER_AUTH_SECRET` |
| `deploy/dokploy/template.toml` | The Dokploy template import | Nothing. Dokploy makes the hostname and the two secrets |
| `deploy/coolify.yml` | Coolify | Nothing. Coolify makes the hostname and the two secrets |

## One hostname for the whole instance

These stacks publish no host port, and they need one public hostname. Send that hostname to the `web` service on port `3001`.

The web app forwards four paths to the API server on the internal network: `/api/auth`, `/rpc`, `/ai/chat` and `/api-reference`. The browser therefore sees one origin. That origin needs no CORS rule and no cookie domain, and the session cookie stays `SameSite=Lax`.

In `deploy/docker-compose.yml` and the Dokploy template, `FREENARY_URL` is that one origin, for example `https://freenary.example.com`. It fills `BETTER_AUTH_URL`, `CORS_ORIGIN` and `PUBLIC_SERVER_URL`. `deploy/coolify.yml` does not read `FREENARY_URL`. Coolify fills the same three variables from the domain of the `web` service. The value must match the browser address bar exactly, scheme included. A different value makes every sign-in fail.

<Callout type="warn">

Keep `BETTER_AUTH_SECRET` after the first start. It seals the credentials that [the setup screen](/docs/self-hosting/setup) stores. A new secret makes the stored bank and email credentials unreadable.

</Callout>

## Dokploy

Dokploy reads `deploy/docker-compose.yml` from the repository. Do these steps in one Dokploy project:

<Steps>

<Step>

### Create the compose service

Create a service of the type **Compose**, and keep the compose type **Docker Compose**. Do not use **Stack**: Docker Swarm ignores the order of the migration step.

In **General**, set the provider to **Git**:

| Field          | Value                                       |
| -------------- | ------------------------------------------- |
| Repository URL | `https://github.com/suiramdev/freenary.git` |
| Branch         | `main`                                      |
| Compose Path   | `./deploy/docker-compose.yml`               |

</Step>

<Step>

### Write the environment

Open **Environment**, and add these lines:

```dotenv
FREENARY_URL=https://freenary.example.com
FREENARY_VERSION=latest
POSTGRES_PASSWORD=<openssl rand -hex 16>
BETTER_AUTH_SECRET=<openssl rand -hex 32>
```

Dokploy writes them to a `.env` file next to the compose file. The `server` service reads that file, so every variable of [Configuration](/docs/self-hosting/configuration) goes here too.

</Step>

<Step>

### Add the domain

Open **Domains**, and add one domain:

| Field          | Value                             |
| -------------- | --------------------------------- |
| Service Name   | `web`                             |
| Host           | `freenary.example.com`            |
| Container Port | `3001`                            |
| HTTPS          | On, with an automatic certificate |

Add no domain for `server`. The web app carries its traffic.

</Step>

<Step>

### Start the Dokploy stack

Press **Deploy**. Dokploy starts `postgres`, then runs `migrate`, then starts `server` and `web`.

</Step>

</Steps>

### The template import

The import fills the compose file, the environment and the domain in one paste. It makes a random hostname under `traefik.me` and the two secrets. Make the import string from a clone of the repository:

```bash
bun run deploy:dokploy
```

In the compose service, open **Advanced**, then **Import**. Paste the string, and press **Import**.

The `traefik.me` hostname serves plain HTTP, so the template sets `FREENARY_URL` to an `http://` address. Before you add your own domain with HTTPS, change `FREENARY_URL` to the `https://` address. Then deploy again.

## Coolify

Coolify reads `deploy/coolify.yml`. It makes the database password, the auth secret and a hostname for the `web` service on its own.

<Steps>

<Step>

### Create the resource

In a Coolify project, select **New**, then **Docker Compose Empty**. Paste the contents of this file:

```text
https://raw.githubusercontent.com/suiramdev/freenary/main/deploy/coolify.yml
```

A Git resource also works. Point it at the repository, and set the Docker Compose location to `/deploy/coolify.yml`.

</Step>

<Step>

### Set the domain

Open the `web` service, and set its domain to your own hostname with the container port:

```text
https://freenary.example.com:3001
```

The `:3001` suffix names the container port. The public address stays on the standard HTTPS port. Coolify then gives the new address to the API server and to the browser.

</Step>

<Step>

### Start the Coolify stack

Press **Deploy**. Coolify starts the four services in the same order as Dokploy.

</Step>

</Steps>

Coolify gives each container the variables of the **Environment Variables** tab. Add any other variable of [Configuration](/docs/self-hosting/configuration) there, then deploy again.

## Another proxy

Portainer, a Traefik of your own or Caddy in a container can run `deploy/docker-compose.yml` too. Attach the `web` service to the network of the proxy, and route the hostname to port `3001`. Get the file with this command:

```bash
curl -O https://raw.githubusercontent.com/suiramdev/freenary/main/deploy/docker-compose.yml
```

A proxy on the host itself, with no Docker network, uses `docker-compose.yml` instead. That file publishes the ports. Read [Behind a reverse proxy](/docs/self-hosting/reverse-proxy#one-hostname).

## Check the instance

Ask the web app for its root page:

```bash
curl -L -o /dev/null -w '%{http_code} %{url_effective}\n' https://freenary.example.com/
```

It prints `200 https://freenary.example.com/login`. Then ask the API server through the same hostname:

```bash
curl https://freenary.example.com/api/auth/ok
```

It answers `{"ok":true}`. A `502 Bad Gateway` from that path means the web app did not reach the `server` service. Read the logs of `server` in the panel.

Then create the first account immediately. The first account to sign in becomes the operator, and it opens [the setup screen](/docs/self-hosting/setup). The bank and email credentials go there, not in the panel.

## The caller address

The rate limits key on the caller address in `X-Forwarded-For`. The proxy of a panel writes the caller address into that header. The web app passes the header on unchanged. One proxy therefore needs no setting.

A CDN in front of the panel needs two settings. The panel proxy removes a forwarded header that comes from an address it does not trust. It then writes the CDN address alone, and all visitors share one rate-limit bucket.

1. Tell the panel proxy to trust the CDN. Dokploy and Coolify run Traefik by default. In the Traefik settings of the panel, add the CDN address ranges to `forwardedHeaders.trustedIPs` of the HTTPS entry point.
2. Set `TRUSTED_PROXIES` to the same ranges. Read [Trusted proxies](/docs/self-hosting/reverse-proxy#trusted-proxies).

## Versions and updates

`FREENARY_VERSION` names the image tag, and `latest` follows each release. Set a version such as `X.Y` to stay on one release line. A redeploy in the panel pulls the images again, and `migrate` applies the new migrations. Read [Updates](/docs/self-hosting/updates).

The database is the named volume of the `postgres` service. Read [Backup and restore](/docs/self-hosting/backup-and-restore).
