# Documentation plan

Plan for the full rewrite of `apps/fumadocs/content/docs/next` (2026-10-17). Every page is written again from an evidence inventory built from the code, not from the previous pages. `docs-review.md` holds the review findings, `docs-validation.md` what was run.

## Readers

| Reader | Section | Goal |
| --- | --- | --- |
| Someone with a server and no instance | `get-started/` | A running instance, the operator account, one linked test bank |
| Anyone signed in | `use/` | What each screen does and how to fix what it shows. No terminal |
| The operator after install | `run/` | Email, sign-in options, updates, backups, failures |
| Operators and developers | `reference/` | Exact variables, provider limits, proxy setups, security model, API |
| Contributors | `contribute` | Run the code, pass the checks, open a pull request |

## Framework

Fumadocs on TanStack Start stays. It already gives Markdown sources, `meta.json` navigation, local search, syntax highlighting, versioned folders and two gates (`docs:check`, `build`). A new framework would add risk and no reader value.

## Evidence

Six read-only inventories, one per area, list every fact with a `path:line` or the command that showed it, and separate verified facts, inferences and unknowns. They are the only source the writers used.

| Area | Main sources |
| --- | --- |
| Product and install | `apps/web/src/app/shell/nav-items.ts`, `docker-compose.yml`, `deploy/**`, `.github/workflows/images.yml`, `packages/instance-config/src/claim.ts`, `apps/web/src/pages/{setup,onboarding}/**` |
| Signed-in screens | `apps/web/src/pages/**`, `features/**`, `packages/api/src/routers/**`, `lib/bank-sync.ts`, `assistant/**`, `en.json`, `fr.json` |
| Operating | `packages/email/**`, `packages/auth/**`, `seal.ts`, `forward-api-request.ts`, compose `:?` messages; backup and restore run against a throwaway PostgreSQL |
| Platform | `packages/env/src/schema*.ts`, `scripts/env-sync.ts`, `packages/instance-config/**`, `providers/**`, `classifier/**`, `cookies.ts`, Dockerfiles |
| API | `apps/server/src/index.ts`, all routers; responses recorded from a running server |
| Contributing | `package.json` files, `turbo.json`, `lefthook.yml`, `ci.yml`, `release.yml`, `scripts/dev.ts`; local path run on a scratch worktree |

## Deliberately excluded

- Internals: tables, pipeline stages, encryption parameters beyond what an operator decides. They stay in `docs/engineering/`.
- Planned features. The sidebar shows Portfolio, Analysis and Goals with a Planned badge; the docs say what exists.
- A generated procedure reference. It needs `.output()` and `.errors()` in `packages/api`, a code change.
- The frozen `0.1` folder.

## Questions for a maintainer

1. Dokploy labels (Advanced → Base64 import, HTTPS toggle) and the Coolify domain syntax: not checkable from the repo.
2. Vendor facts: Powens refuses `http://localhost`, the test connector password, sandbox limits, Enable Banking showing the key once.
3. Internal transfers count in totals today. Intended?
4. Assistant tool totals are always labelled `EUR` (`assistant/tools.ts`).
5. Powens ignores the end of a sync window; Enable Banking sends both ends.
6. `BETTER_AUTH_SECRETS` is read by better-auth and declared nowhere.
7. `instance.check` can't return `NOT_IMPLEMENTED`; the code path is dead.
8. `bun install` needs Node 20.19+, 22.12+ or 24+ for Prisma's preinstall; nothing declares it.
9. Two unit tests fail at HEAD (`deriveMerchantKey` card markers, `categoriseTransaction` direction invariant).
10. Resolved: `next` now links the `dev` branch (`gitConfig.branch` in `apps/fumadocs/src/shared/config/site.ts`), and the snapshot pins it to the release tag. The Dokploy tab names branch `dev`; the snapshot pins it to `gitConfig.releaseBranch` (`main`).
11. Untranslated strings reach French readers: `Other Income` in the Cash Flow chart, raw server errors in three toasts.
