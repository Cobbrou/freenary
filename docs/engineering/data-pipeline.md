# Build-time data pipeline

Durable facts that the code cannot carry in a name. Each bullet names the module it belongs to. Source: comments deleted when the `no-comments` rule was adopted.

## Sources and licences

- `packages/api/scripts/fetch-wikidata-brands.ts › module` — Wikidata's structured data is CC0. It carried 36 000+ brand entities when the pass was written, and about 93 % of them stated an official website (P856), which is why `fetchEntitiesByType` makes P856 a required triple rather than an `OPTIONAL` enrichment.
- `packages/api/scripts/fetch-wikidata-brands.ts › ENTITY_TYPES` — Selection is a direct `wdt:P31` match against each listed class, never the transitive `P279*` closure: the closure times out. WDQS caps a query at 60 seconds, and one query per type keeps each one well inside that.
- `packages/api/scripts/fetch-wikidata-brands.ts › runQuery` — Only 429, 5xx and transport failures retry; any other non-2xx is reported and the query yields no rows. A malformed SPARQL query therefore drops its whole pass silently instead of failing the build.
- `packages/api/scripts/build-merchant-dictionary.ts › NsiLocationSet` — NSI's `locationSet.include` mixes ISO country codes, UN M49 codes, region filenames and inline GeoJSON geometry. Hence `unknown[]`: a member counts as a country only once `resolveNsiCountries` validates it as one.
- `packages/api/scripts/build-merchant-dictionary.ts › categoryPathToOsmTag` — NSI category paths look like `brands/shop/supermarket` or `operators/amenity/fuel`; segments 1 and 2 are the OSM key and value, so the tag is `shop=supermarket`.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeWikidataBrands` — Only a _stated_ P17 is evidence of scope. An absent one means Wikidata does not know where the brand trades, and must not erase the scope NSI declared.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeWikidataBrands` — An unmatched Wikidata brand is added only when it carries a domain: the domain is the evidence that the entity is a real commercial one rather than a Wikipedia article.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCuratedSupplement` — The supplement runs last and overwrites the NSI row on a name collision, so it wins every collision by call order in `buildMerchantDictionary`.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCuratedSupplement` — Curated entries carry no aliases or domains of their own: they are looked up by lower-cased label in the Wikidata artifact, and the first match is kept. `assembleBrands` sorts that artifact by QID, which is what makes "first" deterministic.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCuratedSupplement` — Curated merchants stay unscoped (`countries: []`) rather than being assumed French: the 54 entries span French utilities and global subscriptions alike.
- `packages/api/scripts/build-merchant-dictionary.ts › isEntirelyPlaceName` — Still a stub returning `false`. `generate-place-tokens.ts` exists and the release tarball ships its output, but nothing wires it into this build, so no name is filtered as a place name yet.
- `packages/api/scripts/lib/curated-merchants.ts › CURATED_MERCHANTS` — This list also seeds `fetchCuratedFromWikidata` in `fetch-wikidata-brands.ts`, so adding a name here changes `data/wikidata-brands.json` as well as the dictionary.
- `packages/api/scripts/lib/curated-merchants.ts › CURATED_MERCHANTS` — No multi-line insurer is curated, and the `MULTI_LINE_INSURERS` array that used to hold them is deleted. The flat set has no insurance category: car insurance is `car-fuel`, home, health and liability insurance are `bills-utilities`, and a life-insurance savings contract is `retirement`. A brand name alone cannot pick between those three, and the old array papered over that by claiming `other-insurance` for every one of them. A curated entry exists to assert a category, so an insurer that can assert none belongs in no list; a real policy still reaches the right category through its bank code, its MCC or the reader's own correction.
- `packages/api/scripts/lib/category-map.ts › "amenity=car_rental"` — Car rental maps to `transport-travel` rather than to `car-fuel`, matching MCC 7512 and the issuer-assigned `3000-3999` card-scheme block, which is one category now instead of three runs. A rented car is a trip, and `car-fuel` is the car the reader owns.
- `packages/api/scripts/build-merchant-dictionary.ts › mergeCollisionGroup` — When a brand spans several categories, the highest-priority one wins, never the most frequent. The surviving row's display name is the _shortest_ in the group, tie-broken by id.
- `packages/api/scripts/lib/category-priority.ts › PRIORITY_LADDER` — The ladder only breaks ties inside a collision group; it never rejects a category. A brand whose only NSI evidence sits on an incidental rung keeps it, so a fuel-only brand stays on `car-fuel`.
- `packages/api/scripts/lib/category-priority.ts › CATEGORY_PRIORITY` — Every category names its rung directly, and the separate `LEAF_PRIORITY_OVERRIDE` table is gone: with 27 categories the rung is a property of the category itself, and a second table only let the two disagree. `no-standalone-intent` is the floor, and it holds every category a brand name can never be evidence for — the income side, the investment side, `rent-mortgage`, `taxes`, `subscriptions`, `people`, `cash-withdrawal` and `uncategorised`. Two orderings stay load-bearing: `shopping` sits on `bolted-on-aisle`, so a store's own trade beats its gift aisle, and `restaurants` on `eating-out` must keep losing to `groceries` on `everyday-essentials`.
- `packages/api/scripts/generate-place-tokens.ts › GEONAMES_URL` — GeoNames `cities15000` is the dump of cities with a population above 15 000. The zip holds exactly one member, tab-separated.

## Artifacts

- `packages/api/scripts/download-data.ts › module` — Exit contract relied on by `packages/api/package.json`'s `build:data` (`bun scripts/download-data.ts || bun run build:data:generate`): exit 0 means the release data was downloaded and extracted, exit 1 means the caller must fall back. Every failure path, expected or not, exits 1 — including unexpected defects, through `Effect.catchDefect`.
- `packages/api/scripts/download-data.ts › readGitOriginUrl` — git is legitimately absent at build time (inside Docker without `.git`), which is why a failed `git remote get-url origin` falls through to `GITHUB_REPOSITORY` and then to the hardcoded slug rather than failing.
- `.github/workflows/generate-data.yml › Create release tarball` — The `data-<date>` release always carries `data/place-tokens.json` and `data/merchants.jsonl.gz`, carries `data/wikidata-brands.json` only when it exists, and never carries a `.sig` file.
- `packages/api/scripts/build-merchant-dictionary.ts › buildMerchantDictionary` — Rows are sorted by `id` immediately before `writeArtifact`, so the gzipped JSONL artifact diffs byte-stably between builds.
- `packages/api/scripts/build-merchant-dictionary.ts › writeArtifact` — One artifact, not one per country: every consumer loads it and filters on `countries` in memory, and per-country files would each have to duplicate the unscoped worldwide tail.
- `packages/api/scripts/build-merchant-dictionary.ts › signArtifact` — The signature is Ed25519 over the gzip bytes, written to `merchants.jsonl.gz.sig`. Because the release tarball carries no `.sig`, an instance that takes its dictionary from a release _and_ sets `DICTIONARY_PUBLIC_KEY` fails verification and loses the dictionary stage in silence.
- `packages/api/scripts/generate-signing-key.ts › module` — The printed banner names `verify.ts` as the place to embed the public key. That file embeds no key: `packages/api/src/categorisation/verify.ts` reads `DICTIONARY_PUBLIC_KEY` from the environment, and an unset variable disables verification entirely.
- `packages/api/scripts/build-merchant-dictionary.ts › abandonBuild` and `packages/api/scripts/generate-place-tokens.ts › keepExistingArtifact` — Both scripts keep a stale artifact on purpose: a transient failure with an existing output warns and exits 0. Only a failure with no artifact to fall back on is fatal.
- `packages/api/scripts/build-merchant-dictionary.ts › discardTempDir` — Temp-directory cleanup is best effort on purpose: a failure to remove it must not mask the real result of the extraction.
- `packages/api/scripts/lib/types.ts › DictionaryMerchant.countries` — Absent or empty means worldwide, not "nowhere". Consumers must read it through `isInCountryScope` in `packages/api/src/categorisation/merchant-scope.ts`.
- `packages/api/scripts/lib/types.ts › DictionaryMerchant.osmTag` — Written for auditability only. Nothing under `packages/api/src` reads it; it is null on every Wikidata and curated row.
