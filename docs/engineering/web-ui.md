# Web interface

Durable facts that the code cannot carry in a name. Each bullet names the module it belongs to. Source: comments deleted when the `no-comments` rule was adopted.

## Components

- Overlay containers — a `Drawer` is an inspector on the row selected behind it, and `apps/web/src/pages/budget/ui/transaction-detail-drawer.tsx` is the only one: the transaction list keeps its scroll while a reader corrects one category after another, so the list stays the subject. Every other overlay is a `Dialog`, because its task is self-contained and the page behind it is not part of it. A sheet also carries `swipeDirection`, which drops a half-filled form or a part-finished enrolment on a stray gesture. Judged surface by surface with TypeSafe Jev in September 2026: the sheet won the transaction inspector at p=0.98, the dialog won the category editor at p=0.96 and the two-factor enrolment at p=0.94, and one idiom for all three was rejected at P=0.23.
- `apps/web/src/pages/settings/ui/category-parent-select.tsx › CategoryParentSelect`, `budget/spending-category-picker.tsx › SpendingCategoryPicker` — Base UI types the value handed back by `Select` and by `DropdownMenuRadioGroup` as `any`; both sites annotate it (`string | null`, `string`) so a guard narrows it instead of a shape check.
- `apps/web/src/pages/settings/ui/categories-section.tsx › CustomCategoryParentRow` — the row is a disclosure and a set of actions at once, and a `<button>` may not hold another, so the `CollapsibleTrigger` fills the row and the action cluster is an absolutely positioned sibling above it, the pattern `packages/ui/src/components/sidebar-menu.tsx` uses for `SidebarMenuAction`. The trigger's `pr-39` (156px) is the cluster's measured width plus one gap: four `icon-compact` buttons at 28px with three 8px gaps is 136px, the `right-3` inset is 12px, so the cluster's left edge sits 148px from the row's right edge. Shrink the cluster and the label stops short of it; grow it and the label slides under it — which is why the row's budget-line count sits inside the trigger after the label, and not in the cluster, whose width the gutter has to restate.
- `apps/web/src/pages/budget/ui/spending-category-picker.tsx › SpendingCategoryPicker` — the rows are `categoriesForDirection(direction)` and not the whole taxonomy: 10 on a credit, 20 on a debit, so `Salary & wages` can never be offered on a card payment. `TransactionDetailDrawer` reads that direction off the sign of the amount, which is why the `useMemo` depends on it — an empty dependency array was harmless while the list was constant and would now freeze whichever direction the drawer opened on first. It stays a `Combobox` rather than a `Select`: 20 rows still want a search field, and each row carries its flow section right-aligned and muted, because two categories of one section read alike without it. The trigger is content-sized, so the popup needs its own width floor (`min-w-56`).
- `apps/web/src/pages/budget/ui/transaction-detail-drawer.tsx › TransactionDetailDrawer` — Base UI plays the enter transition only when `open` flips on an already-mounted root, so the root stays rendered and `shownDuringExitAnimation` holds the last transaction to give the exit animation something to draw.
- `packages/ui › MenuRowLabel` takes the _leading_ string children of a sidebar row as the label it truncates and weight-animates, and renders the rest after it, so `shared/sidebar-first-steps.tsx` writes the visible label first and the `sr-only` done/todo span second. Put the span first and the label is empty, which drops the row into the untruncated fallback branch. The svg sizing rule (`[&_svg]:size-[var(--icon-size)]`) is on `SidebarMenuAction` and `SidebarGroupAction`, not on `SidebarMenuButton`. The Fluid Functionalism button takes no `tooltip`, so `shared/sidebar-brand.tsx › SidebarBrand` puts its greeting handlers on `SidebarMenuItem`, where the whole row answers the pointer rather than the glyph alone.
- `apps/web/src/pages/budget/ui/transaction-row.tsx › TransactionRow`, `bank/bank-list.tsx › BankList` — `packages/ui`'s Item primitives fight their callers twice: `ItemTitle`'s own `flex` beats its `line-clamp-1`, so truncation is re-stated on an inner block box (`block w-full truncate`); and `ItemGroup` renders `div[role=list]`, which cannot legally hold `<li>` rows, so the bank list is a real `<ul>`.
- `apps/web/src/pages/login/ui/auth-form-field.tsx › AuthFormField` — `InputGroup` is rendered unconditionally and only the addon is conditional: swapping the group in and out remounts the input and drops focus mid-typing.
- `apps/web/src/app/shell/sidebar-first-steps.tsx › SidebarGroupLabel` wrapper, `ROW_TRANSITION_CLASS` — the group label owns the icon rail's `opacity-0` collapse rule and must not be the animated element, because motion writes opacity as an inline style that no class can outrank; the wrapping `motion.div` is animated instead. The row transition class names every transitioned property explicitly so class merging keeps the button's own collapse transition rather than replacing it.
- `apps/web/src/app/shell/sidebar-first-step-icon.tsx › HIDDEN`, `VISIBLE` — motion resolves a `none` filter target back to `blur(0px)` and re-applies it on every render, leaving a compositing layer that the sidebar's width transition then fails to repaint. Elements that stay mounted animate scale, opacity and translate only; `filter` is for subtrees that unmount.
- `apps/web/src/pages/settings/ui/budget-line-row.tsx › BudgetLineRow` — motion's keyframe parser does not read `oklch()` inside a `box-shadow`, so a `whileDrag` lift leaves the shadow and the scale stuck on the row after the first drop; the lift is CSS driven by `data-dragging`. The drag handle also needs `touch-none`, or a touch drag scrolls the page instead of dragging the row.
- `apps/web/src/pages/onboarding/ui/onboarding-wizard.tsx › OnboardingWizard`, `shared/sidebar-first-step-icon.tsx › SidebarFirstStepIcon` — `AnimatePresence mode="popLayout"` takes the outgoing element out of flow so the incoming one lands in place; `mode="wait"` would leave an empty frame in a vertically centred column. The wizard carries no `layout` prop, because layout projection transform-scales the subtree and visibly squishes the country list's text, and `STEP_CROSSFADE_MASK_BLUR` (4px) masks the frame where both steps overlap, which otherwise double-exposes two blocks of text legibly.
- `apps/web/src/pages/login/ui/auth-credentials-step.tsx › areCredentialsRevealed`, `FOCUS_RING_SAFE_CLIP_CLASS`, `REVEALED_GAP_AND_RING_ROOM_CLASS` — editing the email drops the account mode back to `"unknown"`, so this block reveals and collapses on almost every keystroke: it must use transitions that retarget mid-flight, where CSS keyframes would restart from zero, and focus stays in the email field while an `sr-only` `output` announces what the form now asks for. The inputs' `ring-2` focus ring paints outside their box, so the clip the height animation needs is pushed out with `px-1` and pulled back with `-mx-1`; `FieldGroup` is `flex flex-col gap-4` and a zero-height child still consumes that gap, so the vertical gap lives inside the reveal.
- `apps/web/src/pages/budget/ui/budget-vs-actual-chart.tsx › PlanTrack` — oxlint's `jsx-a11y/control-has-associated-label` searches only two levels deep for a row button's label, which is why the planned and actual bars live in their own component.
- `apps/web/src/app/shell/sidebar-first-steps.tsx › COMPLETION_HOLD_MS` — measured 1400 ms. Without the hold the panel unmounts in the same render that would have ticked the final step, so both the exit animation and the screen-reader progress count report the stale value.
- `apps/web/src/pages/home/ui/assistant-model-selector.tsx › AssistantModelSelector` — the palette renders with `showCloseButton={false}`, because the Base UI dialog in `packages/ui` is narrower and puts its close cross over the search box. The downloading button carries no `aria-busy`: it would tell a screen reader to defer the spinner's own `role="status"`, and the flag never clears because the button unmounts when the load ends. The WebLLM catalogue query stays disabled until the palette opens and WebGPU is known present, because asking for the GPU adapter without one rejects.
- `apps/web/src/pages/home/ui/assistant-chat.tsx › AssistantChat` — the page is `h-[calc(100svh-4rem)]` (the shell header is `h-16`) so the transcript scrolls inside itself and the composer holds still; the composer is `InputMessage` from `@freenary/ui`, which caps its own question box. Settled message rows get constant props so the `memo` on `AssistantMessage` holds and a streamed chunk never re-renders a settled answer's chart.
- `apps/web/src/pages/home/ui/assistant-ui-library.tsx › components`, `budget/recurring-insights.tsx › insightLine` — both shapes are load-bearing typing. The `satisfies Record<keyof typeof ASSISTANT_UI, …>` means a component added in `packages/api` cannot reach the prompt without a renderer declared here; the chain of `return`s typechecks its trailing `insight.trend` only once every other variant has returned, so a new insight kind becomes a compile error. A `default` branch or a lookup table destroys that.
- `apps/web/src/pages/budget/ui/category-filter-menu.tsx › items`, `handleChange` — the server unions a picked group into its categories, so those category rows leave the list while the group is picked and its chip stands for all of them. This menu takes no direction filtering, unlike `SpendingCategoryPicker`: a filter carries no sign, and a reader filtering on `Salary & wages` wants the credits it names. The combobox hands back the whole selection, so the one changed value is recovered by diffing it against the current filter, which keeps `toggleGroup` and `toggleCategory` the single source of what a pick does. The chips box carries its own width floor, wide enough for the placeholder beside the icon, the clear control and the chevron; chips grow it from there.
- `apps/web/src/pages/budget/ui/transaction-rows.tsx › loadMoreCheck` — paging is blocked while the page is stale, because a placeholder page's `hasMore` belongs to the previous view. The empty state is wrapped in `StaleRegion` for the same reason: an unmarked "no transactions" reads as the answer to the control just pressed.
- `apps/web/src/pages/budget/ui/stale-region.tsx › StaleRegion` — the fade is delayed 100 ms so a fast answer never flickers, and the return to full opacity is immediate. The region announces nothing on purpose: several regions go stale on one period change, so the page renders a single status line for all of them.
- `apps/web/src/pages/budget/ui/recurring-table.tsx › WIDEST_COLUMN`, `budget/recurring-kpi-strip.tsx › STRIP_LAYOUT` — the app shell caps content at `max-w-5xl`, so the `@container/budget` content box tops out just under 62rem: a 64rem breakpoint would never fire and six cells across is unreachable. `CELL_HEIGHT` matches a loaded cell so the strip does not resize when data lands.
- `apps/web/src/pages/settings/ui/security-two-factor-dialog.tsx › SecurityTwoFactorDialog` — the backup codes are shown exactly once, so `onOpenChange` refuses to close while the codes stage is on: no backdrop click, no Escape. `showCloseButton` follows the same flag, because a ✕ that the root then refuses reads as a broken control. The `scan` stage keeps a white plate behind the QR code in every colour scheme, because the specification needs a light quiet zone.
- Confirmation dialogs in `apps/web/src/pages/settings/ui/` and `features/bank-connection/ui/disconnect-bank-dialog.tsx › DisconnectBankDialog` are deliberately left open on confirm: a success unmounts the row or the action, and a failure keeps the retry available.
- `apps/web/src/pages/settings/ui/security-passkey-row.tsx › signInReachOf` — WebAuthn `deviceType: "singleDevice"` means the credential cannot leave the authenticator it was made on; `"multiDevice"` means it can, but only once `backedUp` is true (its password manager has synced it).
- `apps/web/src/pages/settings/ui/security-passkey-row.tsx › SecurityPasskeyRow` — a passkey registered by another client can arrive with a blank name, so the stored name and the displayed fallback stay separate values: prefilling the rename dialog with the translated "unnamed" label would save that label as the real name.
- `apps/web/src/shared/lib/ff-icons.ts › ffIcons`, `lib/remix-icon.tsx › remixIcon`, `budget/category-menu-icon.tsx › categoryMenuIcon` — the Fluid Functionalism primitives draw their own glyphs (chevrons, checks, the search magnifier) through named icon slots that default to Lucide, so this app overrides the shared slots with Remix Icon and lets the names it leaves out keep their default. Each adapter caches per icon, because a slot given a fresh closure on every render remounts its icon.
- `apps/web/src/pages/budget/ui/merchant-filter-menu.tsx › MerchantFilterMenu` — a merchant row has to show its period total beside the name, and the label carries the name alone, because the label is what a chip reads out once picked. The row renders the total in its own `tabular-nums` span, and the amounts are held in a map keyed by merchant name.
- `apps/web/src/shared/ui/theme-menu-items.tsx › ThemeMenuItems`, `shared/locale-menu-items.tsx › LocaleMenuItems` — a Fluid Functionalism menu row registers by an index local to the popup it sits in, so these lists number their rows from zero and the sidebar user menu puts each one behind its own `DropdownSubmenu` rather than offsetting them into a shared count. The theme helper is a hook (`useThemeCheckedIndex`) because it reads next-themes; the locale one is a plain `localeCheckedIndex()`.
- `apps/web/src/pages/budget/ui/recurrence-filter-menu.tsx › CONFIDENCE_START` — frequency and confidence sit behind one trigger, because both answer which repeats are in view, and the filter row already carries a company filter and a category filter beside them; the two sections share the popup's running index, so `CONFIDENCE_START` offsets the confidence rows past the frequency rows.
- `apps/web/src/pages/budget/ui/budget-charts.tsx › BudgetCharts` — the companion position carries no card title, because its select trigger already names the view and a title beside it would print the same words twice in a 293px header.
- `apps/web/src/pages/settings/ui/category-picker.tsx › EntryRow`, `budget/spending-category-picker.tsx › SpendingCategoryPicker` — both pickers are comboboxes rather than menus, because a search field beats scanning 20 rows plus the reader's own categories, and a combobox owns that field; the rows are flattened to one array so the filter runs over entries rather than over sections.
- `apps/web/src/pages/settings/ui/category-parent-select.tsx › CategoryParentSelect` — the select carries no label of its own: `id` exists so an external `FieldLabel` can name the trigger. Base UI's value renders the selected item's text and not the icon beside it, so the chosen category's glyph is handed to `SelectTrigger` as `icon`.
- `apps/web/src/pages/budget/ui/no-bank-account.tsx › NoBankAccount` — the call to action points at Settings rather than at onboarding, because onboarding is unreachable once it is complete.
- `apps/web/src/pages/budget/model/recurrence-labels.ts › confidenceVariant` — a measured recurrence reads as a solid badge and a predicted one as a dot badge, so the difference survives a reader who does not read the word.
- `apps/web/src/pages/settings/ui/budgeting-section.tsx › BudgetingSection` — the add-line button is `tertiary` rather than `ghost` because it is the section's primary action, and it carries the same weight as the new-category button in `settings/categories-section.tsx`.
- `apps/web/src/app/shell/sidebar-user-menu.tsx › SidebarUserMenu` — the language and appearance choices each sit behind their own `DropdownSubmenu`, so their rows number from zero inside that popup and the account rows keep their own numbering in the parent. The documentation row opens the documentation for the version the image was built from.
- `apps/web/src/pages/home/ui/assistant-model-selector.tsx › items` — `CommandMenu` resets its highlight when the items array identity changes, so the rows are memoized rather than rebuilt on each render.
- `apps/web/src/pages/login/ui/auth-sign-in-options.tsx › AuthSignInOptions` — the retry button carries no pending state of its own, because the failure block renders only when no answer is held at all, and a retry there returns the query to pending, which replaces the block with the skeleton that names what is being fetched.
- `apps/web/src/app/routes/__root.tsx › RootDocument` — the app predates the Fluid Functionalism size ladder and was designed around 28px controls, so `SizeProvider` defaults to the `compact` step; a surface that wants the 36px step opts in with `size="default"`.
- `apps/web/src/features/bank-connection/ui/bank-list-skeleton.tsx › BankListSkeleton`, `onboarding/onboarding-wizard-skeleton.tsx › OnboardingWizardSkeleton` — a block that stands in for a control reads the size ladder's `control` step instead of a height of its own, so the bank row and the country field occupy the same box before and after the data lands; a height picked by hand shifts the layout on resolve.
- `apps/web/src/pages/budget/ui/amount-filter-menu.tsx › AmountFilterMenu`, `budget/recurrence-filter-menu.tsx › RecurrenceFilterMenu` — a Fluid Functionalism `Button` renders all of its children into one label span, so a trailing count badge carries its own `ml-1.5` rather than relying on a flex gap from the button root.
- `apps/web/src/pages/home/model/use-auto-fold.ts › useAutoFold` — the disclosure stays open while the assistant streams, so everything it produces is on screen, and folds itself `AUTO_FOLD_MS` after the turn ends so the answer is not buried under the reasoning that produced it; a reader who folds or unfolds it owns it from then on, and a replayed answer starts folded and never moves.
- `apps/web/src/pages/home/ui/assistant-transcript.tsx › BOTTOM_SLACK_PX`, `isFollowingNewestRef` — a streamed line can land between the scroll event and the measurement, so the bottom test carries 32px of slack; an exact test lets the follow go mid-answer. The `ResizeObserver` subscribes once, so the follow decision is read from a ref rather than from the render that set it, and the observer fires once on observe as well, which is what lands a transcript restored from the cache at its newest message.
- `apps/web/src/pages/budget/ui/transaction-rows.tsx › hover`, `TransactionRows` — the scroll parent owns the fluid highlight, so it slides between the rows and scrolls with them, and `gapClick: false` keeps the whitespace under the last row inert because a row opens a drawer. Scrolling swaps which rows are mounted, so the rects the highlight tracks describe rows that have since been recycled, and the visible range drives a `remeasure`. The scroll box is not a `ScrollArea`: the virtualizer measures this element and the page itself is what scrolls, so a nested viewport would draw a scrollbar over a box that never overflows.
- `apps/web/src/pages/budget/ui/transaction-row.tsx › TransactionRow` — the row is positioned with `top: offset` rather than a transform, because the list's fluid hover measures rows by their layout offset, which a transform leaves at zero.
- `apps/web/src/pages/login/ui/auth-credentials-step.tsx › renderEmailCheckAdornment` — the input group's addon box is a fixed 28px, so the retry button steps down to `size-6`: the compact icon step fills the box edge to edge, and its hover fill paints over the field's border.
- `apps/web/src/pages/home/ui/assistant-prose.tsx › AssistantProseBody` — raw HTML is not parsed, so a model that writes a tag shows the tag, and the element styles for the rendered Markdown live in `index.css` under the `assistant-prose` slot rather than in this file.
- `apps/web/src/pages/settings/ui/settings-section.tsx › SettingsSection`, `SETTINGS_INSET`, `SETTINGS_BLEED`, `SETTINGS_PROSE` — `Card` draws no background of its own and inherits whatever substrate it sits on, so the section supplies the surface step and every control nested inside it elevates from there; `Card` also hardcodes 12px on its header, content and footer, which is the value `SETTINGS_INSET` matches and `SETTINGS_BLEED` cancels for a list that is the card's whole content. `SETTINGS_PROSE` pins the section's prose at the size the card title and description use, because body copy left to the document lands at 16px inside a 13px card.
- `apps/web/src/pages/settings/ui/settings-row-list.tsx › ITEM_SIDE_BORDER_CANCEL`, `HIGHLIGHT_SQUARE_AT_CARD_EDGE` — `Item` carries a 1px transparent side border that the card's own 12px inset knows nothing about, so the bled row list drops it and lets each row's own 12px padding line its text up under the card title; the hover fill spans the card's full width, and a rounded corner at the card edge would read as a second, smaller surface.
- `apps/web/src/pages/settings/ui/budget-profile-preview.tsx › EMPTY_TITLE_LINE_BOX`, `EMPTY_DESCRIPTION_LINE_BOX` — the loading shell draws its bars inside the line boxes the empty state's own title and description occupy, so the first paint and the answer that replaces it are the same height by construction.
- `apps/web/src/pages/settings/ui/security-sessions-section.tsx › SecuritySessionsSection` — `useFluidHover` routes a click in the list's padding onto the highlighted row, so `gapClick` stays off here: every session row carries its own revoke action.
- `apps/web/src/app/shell/sidebar-first-step-icon.tsx › FirstStepIconContext` — the sidebar row owns the icon column and calls its `icon` prop as `<Icon size strokeWidth className />`, so the step cannot travel down as a prop, and a per-row component built from a closure would change identity on every `done` flip and remount the swap it exists to animate.
- `apps/web/src/pages/home/ui/assistant-chart.tsx › ProgramParse`, `isBroken` — the parse result is stored with the program it came from, because the fence closes one render before the renderer reports on the final program, and judging the previous chunk's result in between flashes a failure for a chart that is fine. The parser is forgiving, so an unknown component or a wrong argument drops the child and leaves a valid but empty card, which is a broken chart to the reader.
- `apps/web/src/pages/onboarding/ui/country-selection-step.tsx › CountryRow`, `CountrySelectionStep` — a row's label is the bare country name, because that label is what a chip reads out once picked and a flag inside it would be announced as "flag: France" before the name; the flag is a separate `aria-hidden` span. The field reports its whole value set on every pick and the step stores that set as it stands, so the clear control empties every chip rather than one. Every country is selectable, and the dot badge marks one with no local bank coverage or categorisation rules behind it.
- `apps/web/src/pages/settings/ui/security-two-factor-section.tsx › SecurityTwoFactorSection` — every password-guarded two-factor endpoint needs the account's password, so an account created through a connected provider cannot enrol at all, and `hasPassword === undefined` (the account list unread or failed) is not the same answer as `false`: the switch waits rather than offering an enrolment that would fail. The switch is the state and the control at once, so the card carries no status badge; neither direction takes effect where it stands, so it opens the step that does and leaves a cancelled dialog with the switch where it was.
- `apps/web/src/features/bank-connection/ui/bank-list.tsx › LIST_VIEWPORT_CLASS`, `BankList` — the height cap belongs to the scrolling viewport, not the root: the root has no definite height of its own, so a `max-height` there clips instead of scrolling, `scroll-fade` is what says the list continues past the cap, and the skeleton shares the class so nothing shifts when the rows land. The fluid-hover scope is the wrapper `div` rather than the list, because the highlight is a `div` that the `<ul>` content model has no room for, and the hover is built with `gapClick: false`: a row carries a connect button and a disconnect dialog, so a click in the gutter between cards must stay inert instead of firing the lit row's.
- `apps/web/src/pages/budget/ui/budget-vs-actual-chart.tsx › PlannedRow`, `BudgetVsActualChart` — spending on a category the reader never planned is unplanned, not an overrun of a plan of zero, so the third label branch stands apart from the over/under pair. One row per category rather than per group: with three groups the chart compared a plan against two bars. In the empty state the link must stay an anchor for routing, so the press animation rides on the `motion.div` around the button rather than on the link itself.
- `apps/web/src/pages/onboarding/ui/onboarding-page.tsx › banksQuery`, `isBankStepReachable` — the institution list is prefetched as soon as a tax residency is picked; the `step === BANK_STEP_INDEX` arm covers a flow resumed into the bank step after the provider became unavailable, which is the one case where `hasBankStep` is false and the step is still on screen.
- `apps/web/src/app/shell/app-sidebar.tsx › NavAreaDisclosure`, `SUB_LIST_VARIANTS`, `CHEVRON_CLASS` — an area row discloses its pages rather than navigating, because it is the area and not a page: while its panel is open the current page's own row carries the selection, so the parent row drops `isActive` instead of lighting a second row and printing a second `aria-current="page"`; closed, the child rows are unmounted and the area takes the selection over rather than lose the location. The icon rail hides every sub-menu, so there an area falls back to `NavRow` and its icon stays a link.
- `apps/web/src/pages/brand-avatar/ui/brand-avatar-page.tsx › DevAvatarPage`, `StateCell`, `gridReplayNonce` — a dev-only board for the brand avatar: not linked from the app, absent from the message catalogs, and meant to be deleted. - `apps/web/src/pages/settings/ui/budget-line-row.tsx › BudgetLineRow` — the row is dragged by its handle alone (`dragListener={false}`), so a pointer down on an input or the category picker still does what it looks like. - `apps/web/src/pages/settings/ui/budgeting-section.tsx › SKELETON_LINES` — one flat list of lines: the category a line carries is what places it in the flow, so splitting the form into revenue, investment and outgoing sections would ask the same question twice. `SKELETON_LINES` is 3, the count a fresh profile tends to carry, so the pending placeholder stands at about the editor's own height and the card keeps its size when the lines arrive.
- `apps/web/src/pages/budget/ui/recurring-kpi-strip.tsx › CELL_CONTROL_HEIGHTS`, `remainingTone` — a cell stacks a figure, its label and the note the commitments cell may carry, which is two and a half control heights read from the size context; the pending placeholder is sized the same way, which keeps the strip from resizing when data lands. - `apps/web/src/pages/home/ui/assistant-model-selector.tsx › AssistantModelSelector` — a model that is still arriving cannot answer, so the button reports the download instead of opening the palette, and the spinner rides the icon slot rather than the `loading` prop, which would draw the label and the percentage — the whole point of that state — at zero opacity. - `apps/web/src/app/shell/auth-layout.tsx › AuthLayout`, `Route.beforeLoad` — the header's `SidebarTrigger` takes `size="icon"`, which keeps the 36px control and sizes the glyph with it; `default` is a labelled size and leaves the glyph at 24px. ## Hooks

- `apps/web/src/shared/lib/use-webauthn-support.ts › isWebAuthnAvailable`, `useWebAuthnSupport` — `PublicKeyCredential` is `[SecureContext]`, so the probe answers `false` on a plain-`http` origin as well as on a browser with no WebAuthn; verified in headless Chromium, the interface object is an _own_ property of `window`, so `Object.hasOwn` and `in` always agree.
