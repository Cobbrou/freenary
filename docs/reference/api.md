This page is generated by `bun run docs:generate` from `appRouter` in `packages/api/src/routers/index.ts` and `apps/server/src/index.ts`. Do not edit it by hand: change the source and run the command again.

The API server answers on these paths. It allows cross-origin calls from `CORS_ORIGIN` alone, with credentials.

| Path | Method | What it serves |
| --- | --- | --- |
| `/rpc/*` | any | The oRPC RPC protocol the web app calls. A procedure `a.b` answers at `/rpc/a/b`. The handler carries oRPC's simple CSRF protection plugin. |
| `/api-reference/*` | per procedure | The same procedures over plain HTTP and JSON, at the routes in the tables below. A `POST` whose `Content-Type` is not `application/json` gets `415 unsupported_media_type`. |
| `/api-reference` | `GET` | The interactive API reference, rendered by oRPC's OpenAPI reference plugin. |
| `/api-reference/spec.json` | `GET` | The OpenAPI document, built per request. Its `servers` entry is the origin of that request. |
| `/api/auth/*` | `GET`, `POST` | Better Auth: sign-up, sign-in, sessions and the sign-in callbacks. Any other method gets `405`. |
| `/ai/chat` | `POST` | The assistant chat. It needs a JSON body (`415 unsupported_media_type` otherwise) and a session (`401 unauthorized`), and answers `503 unconfigured` while no assistant model is set. |
| `/mock-bank/consent` | `GET` | The consent page of the `mock` bank provider. It answers `404` when `NODE_ENV` is `production`. |
| `/` | `GET` | The health check. It answers `OK`. |

## Procedures

Each procedure below answers over both protocols. The HTTP route is the OpenAPI one; the input is the JSON body, and a field without `required` may be left out. [`docs/reference/openapi.json`](https://github.com/suiramdev/freenary/blob/dev/docs/reference/openapi.json) holds the full schemas, the same document `/api-reference/spec.json` serves.

The Access column comes from the middleware of each procedure in `packages/api/src/index.ts`:

- `Public`: no session needed.
- `Signed in`: a Better Auth session; without one the call fails with `UNAUTHORIZED` (401).
- `Operator`: a session of the operator account; without a session the call fails with `UNAUTHORIZED` (401), and with another account with `FORBIDDEN` (403).
