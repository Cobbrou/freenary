This page is generated by `bun run env:sync` from `packages/env/src/schema.ts` and `scripts/env-sync.ts`. Do not edit it by hand: change the source and run the command again.

The API server checks its environment once, at startup. The schema is [`packages/env/src/schema.ts`](https://github.com/suiramdev/freenary/blob/main/packages/env/src/schema.ts). It declares 51 variables with Zod, and `packages/env/src/server.ts` hands them to `@t3-oss/env-core`. The reference below, and `.env.example`, are generated from that one file.

## Core and secrets

Replace the database password and fill the secret. `docker compose up` refuses to start with either one empty, and production refuses the development secret.

```text
openssl rand -hex 16   # database password
openssl rand -hex 32   # BETTER_AUTH_SECRET, 32 characters or more
```

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `BETTER_AUTH_SECRET` | `dev_secret_change_me_at_least_32chars` outside production, required in production | Signs session cookies, encrypts two-factor secrets and backup codes, and signs the bank connection state. | Under 32 characters stops the start. The development default applies outside production alone, so a production start with no value, or with that default, stops. |
| `FREENARY_BUILD_VERSION` | unset | The release the server image was built from. The image bakes it from the `FREENARY_VERSION` build argument, and an operator never sets it. | Empty, or a value that is not `X.Y.Z` such as `dev`, `main` or `sha-*`, turns the update check off. |
| `FREENARY_UPDATE_CHECK` | `true` | `true` asks GitHub once a day for the newest Freenary release, and the account menu of the operator says when it is newer than the running one. | `false` sends no request and shows no notice. A value that is not a boolean string stops the start. |
| `NODE_ENV` | `development` | Picks the runtime mode: `development`, `production` or `test`. | `production` drops the log file drain and turns the cookie warning into a refusal. `test` turns the sign-in rate limits off. The production Compose files and `bun run start` always set `production`. |
| `PORT` | `3000` | The port the API server listens on. It also fills the `BETTER_AUTH_URL` default. | A non-digit character stops the start. In the Docker stack it must stay `3000`, because the healthcheck fetches port 3000 inside the container. Never put it in the root `.env` file, which the `server` service loads whole. |

## Public origins and cookies

The origins a browser reaches. Both default to localhost outside production, which works on the machine that runs the stack and nowhere else. Set both for any other host, with `https://` once TLS sits in front.

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `AUTH_COOKIE_DOMAIN` | unset | The parent domain the API server and the web app share, for example `.example.com`. It keeps the session cookie at `SameSite=Lax` and adds `Domain`. | Three shapes stop the start: a trailing dot, a single label, and a domain that is not a parent of both hostnames. Unset with two hostnames drops the cookie to `SameSite=None`. |
| `BETTER_AUTH_URL` | `http://localhost:3000` outside production, required in production | The public origin of the API server. It builds the sign-in callback URLs and decides the cookie `Secure` flag. | A value that is not a URL stops the start. A wrong origin breaks every sign-in callback. |
| `CORS_ORIGIN` | `http://localhost:3001` outside production, required in production | The public origin of the web app. It sets the CORS allow-list, the passkey relying party and the cookie same-site test. | A wrong value makes the browser report a CORS failure, and it binds passkeys to the wrong relying party. |
| `TRUSTED_PROXIES` | unset | The addresses or CIDR ranges of the proxies in front of the web app, as the web container sees them. The web app replaces `X-Forwarded-For` with the caller address behind them, and rate limits key on it. Compose hands it to the `web` service too. | A malformed entry stops the start. Unset behind a proxy makes every caller share the proxy address and one rate-limit bucket, and the server logs a warning at start. |

## Email

Email delivery — one-time codes, address confirmation and password reset. With no provider Freenary hides those flows instead of offering them. For development, `bun run dev:mail` starts a Mailpit inbox and needs no mail account.

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `EMAIL_FROM` | unset | The envelope sender, for example `Freenary <no-reply@example.com>`. | Both `resend` and `smtp` stop the start without it. |
| `EMAIL_PROVIDER` | unset | Picks the email adapter. Unset means no email provider is connected. | Unset means no email at all: Freenary sends no one-time code and asks for no address confirmation. |
| `RESEND_API_KEY` | unset | The Resend API key. | `resend` stops the start without it. |
| `SMTP_HOST` | unset | The mail host. | `smtp` stops the start without it. |
| `SMTP_PASSWORD` | unset | The SMTP password. | The adapter reads it only when `SMTP_USER` holds a value. |
| `SMTP_PORT` | `465` with `SMTP_SECURE=true`, else `587` | The mail port. | A value above 65535 stops the start. |
| `SMTP_SECURE` | `false` | `true` picks implicit TLS. `false` picks STARTTLS. | With `false` and `SMTP_USER` set, a server that offers no STARTTLS is refused, so the password never travels in clear. A value that is not a boolean string stops the start. |
| `SMTP_USER` | unset | The SMTP user. | Unset means Freenary sends no SMTP credentials at all. |

## Sign-in

Sign-in providers — each optional and inert while unset, so a deployment that configures none of them shows none of the buttons.

Google: https://console.cloud.google.com/apis/credentials

```text
Redirect URI: $BETTER_AUTH_URL/api/auth/callback/google
```

Apple: https://developer.apple.com/account/resources/identifiers

```text
Redirect URI: $BETTER_AUTH_URL/api/auth/callback/apple
```

Any OpenID Connect provider (Authentik, Keycloak, Zitadel, Entra, …).

```text
Redirect URI: $BETTER_AUTH_URL/api/auth/callback/oidc
```

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `APPLE_APP_BUNDLE_IDENTIFIER` | unset | Sets the Apple identity-token audience. | Alone it does nothing, because it is a field of the Apple provider. |
| `APPLE_CLIENT_ID` | unset | With `APPLE_CLIENT_SECRET`, it adds the Apple button. | Alone it adds nothing. |
| `APPLE_CLIENT_SECRET` | unset | With `APPLE_CLIENT_ID`, it adds the Apple button. | Alone it adds nothing. |
| `AUTH_PASSWORD_BREACH_CHECK` | `true` | `true` checks each new password against Have I Been Pwned. | `false` drops the check. A value that is not a boolean string stops the start. |
| `GOOGLE_CLIENT_ID` | unset | With `GOOGLE_CLIENT_SECRET`, it adds the Google button. | Alone it adds nothing. |
| `GOOGLE_CLIENT_SECRET` | unset | With `GOOGLE_CLIENT_ID`, it adds the Google button. | Alone it adds nothing. |
| `OIDC_CLIENT_ID` | unset | With `OIDC_DISCOVERY_URL`, it adds the single sign-on button. | Alone it adds nothing. |
| `OIDC_CLIENT_SECRET` | unset | The client secret. | Unset means a public client. |
| `OIDC_DISCOVERY_URL` | unset | With `OIDC_CLIENT_ID`, it adds the single sign-on button. Point it at the `.well-known/openid-configuration` document. | A value that is not a URL stops the start. |
| `OIDC_PROVIDER_NAME` | unset | The button label. | Unset shows a translated `single sign-on` label. |
| `OIDC_SCOPES` | unset | Comma-separated extra scopes. Freenary always asks for `openid`, `email` and `profile`. | Unset asks for those three alone. |

## Bank providers

Bank provider — leave every value unset to skip the bank-connection step.

Powens: create a domain and a client application at https://console.powens.com, whitelist `https://<web origin>/callback/powens` as a redirect URL of that client.

Enable Banking: register an app at https://enablebanking.com and download the private key .pem file. It needs BANKING_PROVIDER=enable-banking.

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `BANKING_PROVIDER` | `powens` | Picks the provider a new bank connection uses: `powens`, `enable-banking`, or `mock`, which generates bank data for development. | Any other value stops the start, and so does `mock` when `NODE_ENV` is `production`. |
| `ENABLE_BANKING_APP_ID` | unset | The Enable Banking application identifier. | Enable Banking needs both of its values. |
| `ENABLE_BANKING_PRIVATE_KEY` | unset | The Enable Banking PEM private key. | Enable Banking needs both of its values. |
| `POWENS_CLIENT_ID` | unset | The Powens client identifier. | Powens needs all three of its values. |
| `POWENS_CLIENT_SECRET` | unset | The Powens client secret. | Powens needs all three of its values. |
| `POWENS_DOMAIN` | unset | The Powens domain, for example `acme-sandbox`. A value that ends with `.biapi.pro` also works. | Powens needs all three of its values. |

## Assistant

AI assistant — optional. Any OpenAI-compatible chat-completions endpoint: a gateway (OpenRouter, Groq), OpenAI itself, or a local runtime (Ollama, vLLM). Set, it answers chats in Ask, builds and changes dashboards, and serves the assistant API (POST /ai/chat).

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `AI_API_KEY` | unset | The key for that endpoint. | Unset is valid, because a local endpoint needs no key. |
| `AI_BASE_URL` | unset | The base URL of the chat-completions endpoint, with its version path. | A value that is not a URL stops the start. Unset means the instance reports no server model. |
| `AI_MODEL` | unset | The model id as the endpoint names it. | It needs `AI_BASE_URL` too. With either one unset, the assistant route answers `503 unconfigured`. |

## Categorisation

Transaction classifier — optional. It sends a normalised descriptor, merchant and payment facts (never an amount, date, IBAN or account) to the endpoint of TRANSACTION_CLASSIFIER, and to the TRANSACTION_CLASSIFIER_FALLBACK endpoint when that answer is weak. Answers are cached per merchant and per model, so a merchant is asked about once. Each slot names a protocol and its own URL: `system-one` (TypeSafe Jev, Mapika/decider-2b, Laya), `llm` (any OpenAI-compatible endpoint, local or a gateway) or `zero-shot` (Hugging Face). A URL on your own hardware keeps the descriptors on it, which is the recommendation, not a requirement. DICTIONARY_PUBLIC_KEY is the Ed25519 public key PEM from: bun run generate:key

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `DICTIONARY_PUBLIC_KEY` | unset | An Ed25519 public key in PEM form. A value turns signature checks of the merchant dictionary on. | Unset loads the dictionary with no check. A set key with no signature file makes the loader refuse the dictionary, and it warns `Dictionary signature missing:`. |
| `TRANSACTION_CLASSIFIER` | unset | Names the protocol of the classifier asked first for a merchant no rule, no dictionary entry and no correction knows. `system-one` posts the TypeSafe `/v1/systemone` shape, which TypeSafe Jev, `Mapika/decider-2b` and Laya all answer. `llm` posts an OpenAI-compatible chat completion. `zero-shot` posts the Hugging Face zero-shot-classification shape. | Unset calls no model, and such a transaction stays uncategorised. Any other value stops the start. |
| `TRANSACTION_CLASSIFIER_API_KEY` | unset | The key that endpoint expects, if it expects one. | Unset sends no authorisation header at all, which a local endpoint accepts. |
| `TRANSACTION_CLASSIFIER_ESCALATE_BELOW` | `0.85` | The confidence under which the answer of the first classifier goes to `TRANSACTION_CLASSIFIER_FALLBACK`. The default is the confidence the pipeline needs to write a category without asking the reader. | A value outside 0 to 1 stops the start. At 0 the fallback answers abstentions alone. |
| `TRANSACTION_CLASSIFIER_FALLBACK` | unset | Names the protocol of the classifier asked when the first one abstains or answers under `TRANSACTION_CLASSIFIER_ESCALATE_BELOW`. The higher-confidence answer of the two wins, and each is cached against its own model. | It needs `TRANSACTION_CLASSIFIER` too. The same protocol and the same model as the first slot stops the start, because both would share one cache row. |
| `TRANSACTION_CLASSIFIER_FALLBACK_API_KEY` | unset | The key the fallback endpoint expects, if it expects one. | Unset sends no authorisation header at all. |
| `TRANSACTION_CLASSIFIER_FALLBACK_MODEL` | unset | Names the model the fallback endpoint serves. It is part of the cache key, so a change asks every merchant again. | A named fallback with no model stops the start with `TRANSACTION_CLASSIFIER_FALLBACK=<protocol> requires TRANSACTION_CLASSIFIER_FALLBACK_MODEL to be set.` |
| `TRANSACTION_CLASSIFIER_FALLBACK_TEMPERATURE` | `1` | Sharpens or flattens the answer distribution of the fallback before its confidence is measured. It follows the same rule as `TRANSACTION_CLASSIFIER_TEMPERATURE`. | A value that is not a positive number stops the start. A value above 1 lowers the confidence of an over-confident model. |
| `TRANSACTION_CLASSIFIER_FALLBACK_URL` | unset | The URL of the fallback endpoint. The `llm` protocol appends `/chat/completions` to it, and the other two post to it as it is. | A value that is not a URL stops the start. A named fallback with no URL stops it too. |
| `TRANSACTION_CLASSIFIER_MODEL` | unset | Names the model that endpoint serves. It is part of the cache key, so a change asks every merchant again. | A named classifier with no model stops the start with `TRANSACTION_CLASSIFIER=<protocol> requires TRANSACTION_CLASSIFIER_MODEL to be set.` |
| `TRANSACTION_CLASSIFIER_TEMPERATURE` | `1` | Sharpens or flattens the answer distribution before the confidence is measured. At 1 a `system-one` endpoint keeps the statistic it reports, and the other two protocols still measure the distribution themselves. | A value that is not a positive number stops the start. Fit it on merchants your own readers corrected. |
| `TRANSACTION_CLASSIFIER_TIMEOUT_MS` | `10000` | How long, in milliseconds, Freenary waits for a classifier to answer before it leaves the transaction uncategorised. It applies to `TRANSACTION_CLASSIFIER` and to `TRANSACTION_CLASSIFIER_FALLBACK`. | A value that is not a whole number from 1000 to 120000 stops the start. Raise it for a local model on a slow machine. |
| `TRANSACTION_CLASSIFIER_URL` | unset | The URL of the endpoint the classifier asks. The `llm` protocol appends `/chat/completions` to it, and the other two post to it as it is. It reaches a server you run or one somebody else hosts. | A value that is not a URL stops the start. An `llm` endpoint that returns no `logprobs` leaves every answer a suggestion. |

## Compose variables

Only Compose reads these.

| Variable | Default | What it does | Absent or wrong |
| --- | --- | --- | --- |
| `POSTGRES_PASSWORD` | none | The database password. It fills both the container password and the `DATABASE_URL` of `migrate` and `server`. | Compose refuses an unset or empty value. |
| `FREENARY_VERSION` | `latest` | The tag of both published images. | An unset value falls back to `latest`, the newest release. A value that names no tag fails the pull with `not found`. The tags are `X.Y.Z`, `X.Y`, `X`, `latest`, `main`, `dev` and `sha-<7 characters>`. |
| `FREENARY_URL` | none | The public URL of the web app in `deploy/docker-compose.yml`, the stack for a hosting panel. It fills `BETTER_AUTH_URL`, `CORS_ORIGIN` and `PUBLIC_SERVER_URL`, so the API server shares the web app origin. | `deploy/docker-compose.yml` refuses an unset or empty value. A value that differs from the browser origin makes every sign-in fail. |
| `WEB_PORT` | `3001` | The host port of the web app. | — |
| `POSTGRES_PORT` | `5432` | The host port of PostgreSQL. Compose publishes `127.0.0.1:<POSTGRES_PORT>:5432`, so the loopback interface alone gets it. | — |

## Read outside the schema

The web app at runtime and the repository tooling read these from `process.env` directly, outside the schema, so a typo raises no startup error.

| Variable | Read by | What it does |
| --- | --- | --- |
| `DEV_PUBLIC_URL` | the web and documentation dev servers | The address the web and documentation dev servers print in place of their container address. Compose sets it from `WEB_HOST` and `DOCS_HOST`. |
| `PUBLIC_SERVER_URL` | the web app, per request | The API origin the web app hands to the browser in the root document. Compose sets it from `BETTER_AUTH_URL`. A value that is not an absolute URL throws `PUBLIC_SERVER_URL must be an absolute URL such as https://api.example.com, got "…"`. |
| `SERVER_URL` | the web app, on the server side | The origin the web app itself calls while it renders a page. It wins over `PUBLIC_SERVER_URL` there. The web app also forwards the API paths it receives (`/api/auth`, `/rpc`, `/ai/chat`, `/api-reference` and `/mcp`) to it, so one public origin can serve both apps. Compose sets `http://server:3000`. |
| `SKIP_ENV_VALIDATION` | the API server | Any non-empty value turns the whole server schema off. The image sets it in the builder stage alone. |
| `GITHUB_REPOSITORY` | the server image build and the triage scripts | Which repository the merchant data release comes from; the server image build defaults it to `suiramdev/freenary`. GitHub Actions sets it in the `Triage` and `Labels` workflows, and the triage scripts exit without it. |
| `GITHUB_TOKEN` | the server image build and the triage scripts | It lifts the GitHub API rate limit of that download. The build reads it as a BuildKit secret, so the value never enters a layer. The triage scripts call the GitHub API with it to read items, their label history, comments and check runs, to add and remove labels, and to post, edit and delete the triage comment. `scripts/triage/calibrate.ts` reads items and label history with it locally. |
| `OPENROUTER_API_KEY` | the documentation site | The OpenRouter key behind the `Ask AI` panel of the documentation site. That app carries no workspace dependency, so it declares no schema. |
| `OPENROUTER_MODEL` | the documentation site | The model that panel asks. The site carries its own default, so the value is optional. |
| `SUBQ_API_KEY` | the `Triage` workflow | The SubQ Decisions API key the `Triage` workflow labels issues and pull requests with. It is a repository secret; with none, the workflow labels nothing. |
| `GITHUB_STEP_SUMMARY` | the `Triage` workflow | The file GitHub Actions renders as the run summary. The `Triage` workflow writes the labels it added and removed, and the answers behind them, there. |

## Inert variables

These appear in templates but do nothing in production.

| Variable | Why it does nothing |
| --- | --- |
| `POSTGRES_DB` | The production compose file hard-codes the database name `freenary`. The development stack does read the variable. |
| `POSTGRES_USER` | The production compose file hard-codes the user `postgres`. The development stack does read the variable. |
